# ReclassifierEXCEL — действующая архитектура

**Статус:** нормативное описание единственной целевой сборки. Прежде чем менять структуру, проверить фактические зависимости `src/folders/engine-files.json`.

## 1. Исполнение

```text
Локальные Excel и справочники
          │
          ▼
src/folders/index.html + folders.js (оболочка)
          │
          ├─ вкладка «Папки»: выбор каталога, обновление справочников и выгрузок
          ├─ вкладка «Журнал»: мониторинг операций и диагностика
          └─ Worker (Blob; исходники из engine-files.json)
               ├─ DirectoryEngine: сканирование и проверка источников
               ├─ ReferenceManager: распознавание и нормализация справочников
               ├─ ITSM / МБ: потоковая обработка, дедупликация и обогащение
               ├─ Equipment: исходные каталоги и производный Combined
               ├─ Reclassification V4: анализ и диагностика
               └─ SafeExcelWriter: подтверждаемая запись Excel
          │
          ▼
ITSM/export_ITSM.xlsx и MB/export_MB.xlsx
```

Сборка выполняется `build/build_folders.py`, создаёт `dist/Reclassifier_Folders.html` и копию `dist/ReclassifierEXCEL.html`. Технически это **локальная HTML/JavaScript/Worker/Excel-система**. Рабочие корпоративные данные не включаются в сборку.

## 2. Граница модулей

- UI не должен обрабатывать десятки тысяч строк Excel в главном потоке.
- Worker — граница тяжёлой обработки. Данные передаются порционно, когда алгоритм это поддерживает.
- `src/folders/engine-files.json` — источник истины по составу Worker. Нельзя добавлять модуль, не включив его явно.
- Обработчики ITSM, МБ и реклассификации сохраняют устойчивые ключи, происхождение и исходные значения.
- Справочники публикуются только после валидации обязательного комплекта; конфликты не разрешаются выбором первой строки.
- `Equipment_Combined` пересчитывается из исходных каталогов, а не считается самостоятельным источником.
- Чтение, подготовка, проверка и запись двух итоговых Excel выполняются раздельно с контролем версий и восстановлением при прерывании.
- Тяжёлые операции не создают скрытые параллельные полные копии выгрузок без необходимости.
- Нельзя автоматически публиковать результаты реклассификации V4 без инженерной проверки.

## 3. Данные

Рабочая директория: `Catalogs/`, `ITSM/`, `MB/`. Семь основных справочников ITSM: `reclassification`, `drivers`, `customers`, `type_request`, `initiators`, `exceptions`, `problem_grade`. Дополнительные каталоги оборудования и классификатор отказов распознаются по действующим правилам.

ITSM: стабильный ключ заявки `number` (Excel «Номер»). МБ: стабильный ключ задачи `recordKey`, возможны несколько задач на одну заявку ITSM. Несколько PRB на одном классификационном пути допускаются, без автоматического выбора.

Справочные контракты: `src/folders/engine/references/reference_config.js`; схемы полей ITSM и МБ — соответствующие модули в `src/js/modules/`.

## 4. Навигация

Настоящая оболочка находится в `src/folders/index.html`; контроллер — `src/folders/folders.js`. Новые рабочие разделы следует включать сюда, а не создавать отдельные версии навигации. При создании RCA Master существующая левая консоль должна переключаться на внутреннее меню модуля с кнопкой возврата.

## 5. Локальная приёмка

Единый локальный процесс — `tools/local-ci.ps1 verify`: проверка файла зависимостей, сборка и тесты «Папок», тесты независимого двигателя реклассификации. Без автозапуска облачных вычислений.

## 6. Источники архитектуры

- `build/build_folders.py`
- `src/folders/engine-files.json`
- `src/folders/workspace/`, `src/folders/engine/app/directory_engine.js`
- `src/folders/engine/app/safe_excel_writer.js`
- `src/folders/engine/workers/folder_export_processor.js`
- `docs/reclassification/folders-engine-contract.md`

Исторические альтернативные сборки и технологии не являются источником архитектурных требований для этого репозитория.
