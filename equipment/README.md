# Equipment Combiner

## Назначение

Раздел **Данные → Оборудование** управляет пятью входными каталогами и одним производным набором `Equipment_Combined`.

Рабочий сценарий обновления теперь двухфазный:

1. пользователь выбирает от 1 до 8 Excel-файлов в карточке `Equipment_Combined`;
2. **Обработать** — распознать, проверить и нормализовать загруженные источники, затем построить кандидат на полном текущем наборе;
3. **Распределить данные** — заменить только реально загруженные источники и опубликовать полностью пересчитанный `Equipment_Combined`.

Пять рабочих источников:

- `CatalogMountedEquipment`;
- `CatalogStationaryEquipment`;
- `CatalogTransport`;
- `CatalogTransport StartPoints`;
- `CatalogZabbixEquipmentTree`.

В партии может присутствовать ранее выгруженный `Equipment_Combined`. Он используется только как контроль структуры и не является источником пересчёта.

## Частичное обновление

Если загружен только один из пяти источников, остальные четыре берутся из текущего рабочего baseline. `Equipment_Combined` не патчится построчно: он всегда строится заново из полного набора источников.

Для Mounted и Stationary каждый файл считается полным снимком перечисленных в нём рудников. Строки, исчезнувшие из снимка, удаляются только в этих рудниках. У строк с совпадающим ID обновляются только колонки, присутствующие в файле. Пустая ячейка в такой колонке очищает значение. Например, при загрузке ЗФ сохраняется `group_number` из ранее загруженного КФ.

В одной партии можно загрузить разные варианты колонок для одного рудника, если наборы ID в них совпадают. Строки объединяются по ID. Если общая колонка содержит разные значения, используется значение из файла, обработанного последним. Для разных рудников можно загружать файлы независимо от формата.

До нажатия **Распределить данные** рабочие каталоги не изменяются.

В SQLite-режиме зависимость `Equipment_Combined` от пяти исходных каталогов объявлена в Dataset Catalog. После подтверждённого изменения любого из этих источников synchronization barrier очищает derived-кэш и сразу пересчитывает `Equipment_Combined` из пяти актуальных SQLite Dataset. Изменение несвязанного Dataset пересчёт Equipment не запускает. Если хотя бы один обязательный Equipment-источник отсутствует, пересчёт завершается ошибкой синхронизации вместо использования старого Combined или HTML fallback.

Если в общей очереди БД одновременно подготовлено несколько Equipment-файлов, они применяются как один атомарный пакет. До записи система строит полное кандидатное состояние всех пяти источников и один кандидат `Equipment_Combined`. Только после успешного расчёта Repository выполняет все REPLACE в одной SQLite-транзакции. Ошибка любого файла или Combined-процессора откатывает весь пакет. После COMMIT уже рассчитанный Combined публикуется в Runtime без повторного запуска процессора.

## Поля и технические ключи

Публичные записи источников сохраняют согласованные поля. Неодобренные поля допускаются во внутреннем техническом индексе, если они нужны для связи и полного повторного пересчёта.

- Mounted: до 16 публичных полей. Заголовок `identifier_number` принимается как вариант `identifier`.
- Stationary: до 18 публичных полей. Колонка `unit_department` может отсутствовать.
- Transport: 5 публичных полей; `unit + name` используется как технический ключ.
- StartPoints: 0 публичных полей; `unit + name` используется как технический индекс.
- Zabbix: 6 публичных полей; исходное `equipment` используется как технический ключ связи.

## Объединение

1. Stationary и Mounted объединяются вертикально по именам колонок.
2. Transport присоединяется только к Mounted:
   `Mounted.unit + Mounted.transport -> Transport.unit + Transport.name`.
3. StartPoints индексируется по `unit + name`.
4. Zabbix присоединяется по `Zabbix.equipment -> Equipment.id`.
5. Несколько строк Zabbix для одного Equipment агрегируются через ` / ` без размножения Equipment.

## Расчётный статус эксплуатации

В `Equipment_Combined` статус рассчитывается в колонке

`Статус эксплуатации`

Правило:

- `not_working_since` пусто → `Активен`;
- `not_working_since` непусто → `Не активен`.

Если непустое значение `not_working_since` не распознано как дата, обработчик выдаёт предупреждение качества данных, но бизнес-статус всё равно определяется как `Не активен` по факту наличия значения.

## Начальные данные

В репозитории и сборке нет каталога оборудования или стартового набора. Для пересчёта `Equipment_Combined` пользователь должен загрузить нужные источники в подключённую SQLite-базу. Если обязательного источника нет, пересчёт завершается ошибкой; скрытый HTML fallback не используется.

Правила: **Equipment Merge Rules 1.1.0**.
