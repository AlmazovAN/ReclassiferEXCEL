# PR-02. Версионное JSON-хранилище RCA

В выбранной рабочей папке при первой записи создаётся `RCA/`. Снимок одной карточки хранится в `problems/<uuid>/<revision>-<uuid>.json`. UUID снимка позволяет повторить запись после сбоя, сохраняя частично записанный файл для диагностики.

Файлы `indexes/index-<поколение>.json` содержат проекции карточек, имена снимков и SHA-256. Очередь сериализует операции репозитория. При наличии Web Locks вкладки одного источника используют общий замок. Перед записью сверяется ожидаемая ревизия. Индекс публикуется после записи и контрольного чтения снимка. Для записи файлов запрашивается эксклюзивный поток.

Реестр читает последний структурно валидный индекс. При открытии карточки отдельно проверяются контрольная сумма, схема, ID и ревизия снимка. При повреждении читается предыдущая опубликованная ревизия и возвращается список затронутых файлов. Повреждённые файлы сохраняются. При отсутствии валидного индекса запись блокируется. Восстановление из одного лишь набора неопубликованных снимков требует отдельного решения пользователя.

В режиме импорта папки используются только ссылки на файлы из её каталога `RCA/`. Запись требует выданного разрешения браузера. Состояние «Требуется экспорт JSON» оставляет черновик в памяти. Пользовательское создание карточки и экспорт архива предусмотрены последующими этапами.

Проверки выполняются на виртуальной файловой системе. Выдача разрешений и конкурирующая запись из нескольких реальных вкладок требуют отдельной браузерной проверки.

С этапа E5 словари публикуются в том же поколении индекса, что и ссылки на снимки. Старые индексы без поля словарей читаются как пустые словари. При импорте снимки пакета записываются и перечитываются до публикации общего индекса. Если публикация прервана, остаётся доступным прежнее поколение. Лимит переносимого JSON составляет 16 МиБ.
