# RCA-PR13. База второй очереди

Исходное состояние — чистая ветка `main`, коммит `2ee830d`. Локальный `tools/local-ci.ps1 verify` до изменений прошёл 18 тестов приложения и 12 проверок V4. SHA-256 целевой сборки — `8f8d1875af0232dfecb9c563db419aa57f3d6a0afbb3afcf09619b03a51c743c`.

## Карта сборки

| Контур | Фактическая зависимость |
|---|---|
| UI | `index.html` → встраиваемые CSS и JS из `UI_ASSETS` сборщика → `folders.js`. Журнал и выбор папки загружаются перед оболочкой. RCA использует модель, валидацию, JSON-репозиторий, представления и отчёт из того же скрипта страницы. |
| Рабочая папка | `folders.js` передаёт контекст записи, импорта или отсутствия папки в `state.js` → `repository-json.js`. Репозиторий публикует снимки и индекс только внутри `RCA/`. |
| Excel Worker | `storage.js`, `limits.js`, SHA-256 → 50 модулей из `engine-files.json` → `workflows/run-reclassification.js` → `worker.js`. Библиотека XLSX загружается первой из манифеста. |
| Справочники и экспорт | Конфигурация и нормализация справочников → менеджер и движок каталогов. Правила ITSM и процессоры ITSM/МБ используются конвейером экспорта. Сохранение выгрузки идёт через явную команду UI и действующий `safe_excel_writer.js`. |

Структурная проверка читает фактические списки сборщика. Она проверяет наличие файлов, дубли, пересечения UI и Worker, порядок точек входа и появление прямых вызовов записи или удаления вне существующих модулей хранения. Это статический контроль границ. Проверки назначения файла, версии и явного действия пользователя остаются обязанностью действующего Excel Writer. Новые читатели PRB, ITSM и шаблонов получают входные файлы для чтения.

## Контракты для следующих этапов

| Объект | Предлагаемая версия и данные |
|---|---|
| Официальная запись PRB | Отдельная схема v1. Ключ — нормализованный PRB с сохранёнными цифрами. Официальные название, статус ITSM, даты, проект, ответственный и исходный контекст хранятся отдельно от ручных данных. Снимок справочника хранит хеш и имя файла, дату загрузки, количество строк и предупреждения. |
| Компактный расчётный индекс | Отдельная схема v1. Строка по ключу PRB × участок × календарный день содержит `incCount` и `mbLaborHours`. Метаданные фиксируют источник, диапазон, версию правил и диагностику дублей и пропусков. Нулевые часы допустимы. |
| Шаблон плана | Отдельная схема v1. Нормализованный код, название сценария, происхождение и упорядоченные шаги со стабильными `stepId`, `predecessorIds`, длительностью и ролью. |
| Экземпляр плана | Отдельная схема v1. UUID, ссылка на мероприятие и версию шаблона, дата начала и собственная редактируемая копия шагов. Нулевая длительность сохраняет одинаковые начало и окончание. |
| Расширенный паспорт RCA | Текущая схема карточки v1. При совместимых добавлениях новые поля необязательны. Официальная ссылка и данные инженера независимы. Версия меняется при несовместимом контракте с явным преобразованием в памяти и тестом сохранности. |

## Проверка совместимости

Тест вручную размещает старый снимок и индекс v1 с реальной контрольной суммой в виртуальной файловой системе. Открытие и экспорт проверяют все поля, связи, историю и неизвестное расширение. Сравнение исходных файлов подтверждает, что чтение не меняет их байты и не создаёт новую ревизию. Это испытательный контур для будущих миграций. В PR13 рабочий формат остаётся v1.

Синтетические строки в `tests/fixtures/rca-pr13.cjs` покрывают неоднозначный ProblemGrade, Excel-дату, незнакомый статус PRB, совпадающий и конфликтующий дубль INC, пропуск даты, нулевые часы и девять шаблонов с 74 шагами.
