# PR 8 — Экспериментальный прогноз завершения текущего месяца для ВБР и КТГ

## 1. Назначение и статус

Реализован **прогноз итогового значения незавершённого календарного месяца**, а не прогноз будущих месяцев и не изменение утверждённой методики расчёта KPI. Рассчитывается только локально, на базе имеющихся KPI Results и их **исходных расчётных компонентов**. Пользователь должен отличать:

- **Факт за выбранный месяц**: существующий `KpiCalculator`, число и трассировка в `snapshot.results`.
- **Прогноз итога месяца**: `snapshot.kpiView.cards.vbr.forecast` / `ktg.forecast`, `forecastType: current-month-nowcast`, отдельные метод и диагностические сведения.

Прогноз включается **только** для текущего месяца по времени `snapshot.calculatedAt` и при наличии достаточной полной истории. Для прошлого/будущего периода прежний `Forecast Engine.predict` по ВБР/КТГ остаётся в режиме `historical-data-required`: исторические численности оборудования не загружены. PR9 добавит прогноз на SVG-график (прерывистая линия, полупрозрачная точка и раскрытие компонентных оснований); PR8 отвечает за проверяемую математику и передачу значения.

## 2. Источники данных и фильтры

Источник — помесячные Results Calculator в текущем Report Snapshot, рассчитанные **при тех же фильтрах рудника и класса оборудования**. Никакого второго отбора необработанных событий для прогноза.

- **ВБР:** `failureCount`, `equipmentCount` из Calculator; `failureCount` основан на подтверждённых решением реклассификации отказах INC с датой завершения и резервной датой закрытия; `equipmentCount` из Drivers.
- **КТГ:** `incidentHours`, `plannedMaintenanceHours`, `unplannedMaintenanceHours`, `otherHours`, `calendarHours`, `equipmentUnits`. ITSM-источник длительности: `preBacklogHours`, месяц по `createdAt`, деление по действующей классификации работ.
- История: минимум **6 обучающих завершённых месяцев + 2 месяца для проверки**. Максимум 12 месяцев. Нужна непрерывная последовательность сразу до прогнозируемого месяца. Каждый месяц должен иметь `dataState=available`, численные неотрицательные компоненты и отсутствие `diagnostics.partialCoverage`.

## 3. Формализованный алгоритм

Для каждого прогнозируемого компонента `C` по предыдущим месяцам `i`:

```
Days_i   = календарное число дней в месяце i
Rate_i   = C_i / Days_i                     [единиц компонента / сутки]
```

Применяется МНК по равномерным месячным наблюдениям `Rate_i` (**linear-trend**, тот же исходный адаптер Forecast Engine). На двух последних завершённых месяцах выполняется ретроспективная проверка: `MAE_linear` сравнивается с `MAE_last-value`. Если линейная модель хуже, для соответствующего компонента выбирается последняя наблюдавшаяся суточная интенсивность; это **явно отражается** в `methodComponents`.

Затем:

```
RemainingDays = Days_selected - dayOfMonth(calculatedAt)
Rate_predict  = max(0, predictedDailyRate)
C_end         = C_observed + RemainingDays × Rate_predict
```

**ВБР, прогноз:**

```
VBR_end = (1 - FailureCount_end / EquipmentCount_current) × 100
```

**КТГ, прогноз:**

```
PlannedMaintenanceHours_end = PlannedMaintenanceHours_observed + RemainingDays × Rate_predict
AvailableHours_end          = CalendarHours_current - PlannedMaintenanceHours_end
ProductiveHours_end         = CalendarHours_current - (
  IncidentHours_end + PlannedMaintenanceHours_end +
  UnplannedMaintenanceHours_end + OtherHours_end
)
KTG_end = ProductiveHours_end / AvailableHours_end × 100
```

Итог ограничивается диапазоном **0–100% только в прогнозной величине**, с фиксацией `bounded=true`; первичные компоненты и фактические значения **не ограничиваются/не изменяются**. У КТГ учитывается существующее допущение `T_TO_plan=T_TO_fact`.

## 4. Границы применимости

- Прогноз считается **предварительным и экспериментальным**, не является официальным KPI.
- Используется текущая численность Drivers; **временного ряда состава оборудования нет**. Изменения парка в прошлом не моделируются.
- Проверка актуальности выгрузки относительно `calculatedAt` недоступна по текущим агрегированным компонентам. Значение `asOf` — время расчёта, **не подтверждённая полнота сведений за день**.
- Не прогнозируется текущий календарный день: прибавляются только будущие календарные дни, исключая дублирование уже наблюдаемой части текущего дня. Качество наблюдений за текущий день не подтверждено.
- Если в истории есть разрыв, частичный месяц, недостоверный компонент, отсутствующий источник, а текущий показатель не рассчитан — значение **не выдаётся** (`dataState=insufficient`, `reason`).
- Расчёт не выполняется до **4-го календарного дня**, в последний календарный день и вне соответствующего текущего месяца.
- Если текущий КТГ имеет частичное наблюдение по неполным длительностям, прогноз сохраняет статус `provisional-partial` и явное предупреждение. Значение нельзя воспринимать как полный замер просто потому, что формат — процент.
- Конфиденциальные исходные записи в прогноз не включаются: только компоненты KPI, идентификатор метода и диагностические признаки.
- `forecast.methodId` отделён от `formulaVersion` Calculator. Никакой переоценки предыдущего или текущего Report Snapshot.

## 5. Проверка

`tests/test_kpi_current_month_forecast_pr8.js` проверяет компоненты, линейную экстраполяцию и сравнение с базовой моделью, календарные дни, ВБР/КТГ, статусы недостаточности, защиту знаменателя, `Object.freeze` и сохранение существующего отказа прогнозировать будущий месяц ВБР/КТГ.

`tests/test_kpi_report_view_model.js` проверяет интеграцию в Snapshot, неизменность наблюдаемого KPI и отсутствие nowcast для исторических периодов и первичного Snapshot без истории.

`tests/test_step9_browser_offline.js` в реальном локальном HTML контролирует различие между наблюдаемыми значениями и экспериментальным прогнозом и выполняет прежние проверки KPI, SQLite, PDF и истории.
