# PR-9 — Завершение импорта: подтверждение покрытия, PDF и паспорт

## Принцип

Источник истины для даты выгрузки — **отдельное подтверждение полного покрытия
накопительного Dataset пользователем**, а не дата последнего события, дата
создания файла, дата загрузки и не текущий календарный день.

В разделе «Дашборд → Покрытие данных ITSM и МБ» после применения выгрузки
оператор выбирает каждый источник, указывает:
- `coverageFrom` — с какого дня в активном накопительном Dataset
  присутствуют ВСЕ релевантные обращения/задачи;
- `coverageThrough` — последний полностью подтверждённый день;
- отдельную явную отметку о полноте всех дней **по всем рудникам и
  классам оборудования**, необходимым для показателя.

Только после явной отметки сохраняется `meta.reportingCoverage`:
`{confirmed:true,basis:'source-export-cutoff',coverageFrom,
coverageThrough,certifiedBy:'user-explicit-dataset-attestation',
certifiedAt,scope:'entire-accumulated-dataset'}`.

Нельзя подтверждать весь Dataset на основании последней строки Excel или
выгрузки **только одного рудника**. В таком случае интервал остаётся
неподтверждённым и числовой прогноз недоступен. Приложение может
проверить календарные границы и факт явной отметки, но **не может
автоматически доказать полноту корпоративного источника**.

## Хранение

### Режим HTML Dataset Store

Подтверждение изменяет только `meta` текущего активного экземпляра
через Dataset Lifecycle Manager. Его строки и расчёты не меняются.
Если набор был встроенным baseline, он становится изменённым пользовательским
Dataset, чтобы **«Скачать HTML с данными»** включил метаданные вместе
со строками. Повторное открытие такого HTML восстанавливает подтверждённый
интервал; снимки повреждённых данных отклоняются целиком.

Простая загрузка **новой** выгрузки ITSM или МБ готовит новое поколение
Dataset с неподтверждённым покрытием: подтверждение прошлого поколения
не наследуется молча.

### Режим авторитетной SQLite

`ReclassifierDatabaseRepository.setReportingCoverage(id, declaration|null)`
выполняет метаданные-only транзакцию:
пишет `dataset_state.state_json.reportingCoverage`, обновляет времена
реестра/БД, инвалидирует Runtime Repository и расчётные кэши.
**Данные, schema version и активная revision не изменяются**.
Экспорт `Reclassifier.db` содержит эти метаданные.

Новый UPSERT сбрасывает прежнее подтверждение, поскольку состав данных
изменился. При первичном bootstrap копия ранее явно подтверждённого
HTML Dataset сохраняет аттестацию без изменения строк. Отзыв
подтверждения удаляет поле `reportingCoverage`.

## Прогнозы и представления

Для ВБР/КТГ прогнозируются компоненты, затем формула процента.
Для трудозатрат прогнозируются часы оставшихся дней, а накопленный факт
отображается отдельно от прогноза итога. Существующие
`reporting-month-nowcast` и `reporting-month-volume-nowcast`
из PR-2/PR-7 **не меняют формулы Calculator**.

- Паспорт трудоёмкости показывает фактические часы, ожидаемые часы
  оставшегося периода, полный прогноз, дату границы, методы/версии и
  ревизию источника.
- PDF читает трудовые прогнозы из `Report Snapshot.kpiView.cards`
  (total/avr/maintenance/corrective). Прогнозы указаны текстом рядом
  со структурой трудозатрат и не заменяют фактические KPI.
- PDF fingerprint учитывает значение/метод/версию/границу прогнозов
  и дату подтверждённого покрытия в метаданных источников.
- Операционное количество INC в месячном графике рассчитывается через
  `buildOperationalChartData('inc','month',...)` из PR-7 и визуализируется
  отдельно (PR-8); индивидуальный паспорт KPI INC не предусмотрен,
  поскольку `inc` не является процентным KPI Calculator.

## Проверки и границы

Тесты: `test_kpi_source_facts.js`,
`test_html_snapshot.js`,
`test_reliability_pdf.js`,
`test_reliability_report_service.js`,
`test_step9_browser_offline.js`.
Последний проверяет подтверждение/отзыв в SQLite на
**тестовых** значениях и целостность экспортированных байтов, не
утверждая, будто встроенный корпоративный baseline автоматически полон.

Тестирование на конкретных *пользовательских* выгрузках требует их загрузки
оператором и независимого подтверждения границ. Без подтверждения
приложение продолжает показывать фактические KPI и честный статус
недоступности прогноза.
