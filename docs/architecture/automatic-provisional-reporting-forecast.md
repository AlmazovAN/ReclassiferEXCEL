# Автоматическое предварительное прогнозирование без ручного подтверждения

## Исправленная модель

PR-9 ошибочно возлагал ответственность за полноту корпоративной выгрузки
на пользователя локального аналитического приложения. Оператор не обязан
знать внутренние гарантии загрузчиков и не должен вводить предполагаемую
дату окончания выгрузки. Панель «Покрытие данных ITSM и МБ» удалена.

Предусмотрены **два различных режима доказательств**:

1. **Подтверждённый** `source-export-cutoff`: источник сам гарантирует
   период полного покрытия в метаданных. Сохраняется прежняя строгая
   логика Forecast Engine.
2. **Предварительный** `observed-event-horizon`: когда такого поля нет,
   сервис определяет последнюю *наблюдаемую* дату завершённого INC
   (`completedAt`) или валидной задачи МБ (`factDate`) из кэшированной
   операционной подготовки, плюс доступную дату `freshness`. Она НЕ
   гарантирует, что все события за прошедшие дни присутствуют в Dataset.

Отчётный месяц при предварительном режиме — календарный месяц последнего
наблюдаемого события источника. Если последний факт датирован последним
днём месяца, остатка дней нет и прогноз не требуется. Если наблюдение
ранее окончания месяца и прошло хотя бы 4 дня, возможен прогноз
оставшихся календарных дней, независимо от текущей системной даты.

## Формулы

Для абсолютных метрик:
`прогноз итога = наблюдаемый факт + остаток дней * суточная интенсивность`.
Для процентных KPI прогнозируются компоненты, после чего применяется
действующая формула ВБР/КТГ — сами KPI в процентах не умножаются на дни.

Предварительный режим по умолчанию использует
`observed-run-rate`, не требует 8 полностью закрытых месяцев.
Доступные прежние методы `last-value`/`linear-trend` остаются
для подтверждённых периодов и выбора пользователем; принудительное
подтверждение даты не требуется.

В результате проставляется `coverageBasis='observed-event-horizon'`,
`quality.status='provisional-observed-only'` и пояснение о
неизвестной полноте источника. Прогноз не перезаписывает фактический KPI.

## Границы достоверности

Отсутствие событий после даты X — не доказательство, что выгрузка
содержит всю статистику до X. Использование X как горизонта оценки
может завысить или занизить экстраполяцию, особенно в разреженных
данных. Это экспериментальная *оценка возможного итога*, а не
подтверждённая полная статистика. При появлении новых строк модель
автоматически пересчитается на новом Dataset.

Если источник не содержит пригодных дат, значения отсутствуют или
месяц уже достиг последнего календарного дня, пунктир не строится.
UI показывает причину; выдумывать прогноз нельзя.

## Представление

Режим PR-8 сохраняется:
- ВБР/КТГ: пунктир от последнего завершённого месяца к бледному прогнозу,
  без промежуточной точки процента;
- INC/часы: накопленный факт и отдельная бледная прогнозная точка на
  том же месяце, вертикальный пунктир между ними;
- на графике есть пояснение о предварительном характере и
  отсутствии гарантий полноты данных.

### Технические контракты

`ReclassifierKpiOperationalSeries.observedRange()` кэширует диапазон
дат пригодных источниковых событий, без повторного чтения Excel/SQLite
в модуле прогнозирования. `buildReportingCoverage()` создаёт только
вспомогательный предварительный объект; исходные Dataset и метаданные
`meta.reportingCoverage` не меняются.

Реальные даты окончания корпоративного экспорта могут быть известны
только его производителю, поэтому в интерфейсе **не используется
слово «подтверждено»** для автоматически выявленного горизонта.
