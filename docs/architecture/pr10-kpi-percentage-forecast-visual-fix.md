# PR-10 — Визуализация прогнозов процентных KPI

## Дефект

В графике «Показатель KPI» последний наблюдаемый месяц мог выглядеть
как окончательно рассчитанное фактическое значение, даже если источник
считает отчётный месяц неполным. Операционные графики INC/чел.-ч при этом
уже выводили факт и пунктирный прогноз.

До PR-10 реальный путь `Report Service → Chart View Model → SVG` для
KPI не был обязательной частью браузерной приёмки: тесты проверяли
доступность forecast в сервисе и SVG на отдельных синтетических fixtures.

## Правила

Для **ВБР** и **КТГ**:
- Если `forecastType='reporting-month-nowcast'`,
  `dataState='available'`, `forecast.horizon` совпадает с последним
  видимым месяцем, а `forecast.observedValue` — с его фактом, SVG
  **не** рисует промежуточный процент сплошной конечной точкой.
- Последний участок от предыдущего завершённого месяца до прогноза —
  **пунктирный**. Конечная прогнозная точка пустая/приглушённая,
  подпись прогноза бледнее и сопровождается подсказкой.
- Фактический процент не теряется, остаётся в Calculator и tooltip.
  Значения в PDF читаются из Report Snapshot, не из SVG.
- Если конец месяца не покрыт, а прогноз не вычислен по объективной
  причине, **не** рисуется вымышленный прогноз. Вместо этого
  показывается причина, а также предупреждение, что наблюдаемый
  процент промежуточный.
- Для полностью завершённого месяца сохраняется обычная сплошная
  линия; ретроспективный прогноз за него не создаётся.

Для абсолютных INC/трудоёмкости схема PR-8 (факт плюс вертикальный
пунктир к итогу) неизменна.

## Изменения расчётного контракта

`buildKpiChartMultiDataInner` использует неизменяемый
`forecast` отдельно в каждой комбинации «рудник × класс × наименование
оборудования», не переносит общую карточку KPI в детализацию.

Дополнительно:
- `forecastMethodId` задаётся пользователем *необязательно*;
- режим `Автоматически` оставляет выбор метода Forecast Engine:
  `observed-run-rate` для предварительных наблюдаемых данных,
  `linear-trend` для сертифицированного полного интервала;
- история для прогнозирования загружается отдельно от видимого окна
  и только в нужной длине (0 / 1 / 8 завершённых месяцев);
- для несоответствующего отчётного месяца возвращается диагностический
  статус `insufficient`, вместо отсутствующего объекта прогноза.

**Формулы VBR, KTG, подготовка и перечень источников не меняются.**

## Приёмка

- `tests/test_reliability_report_service.js`: синтетический источник
  отдаёт точные прогнозы и оба значения (`observedValue`, `value`)
  для ВБР/КТГ, независимо от видимого окна.
- `tests/test_forecast_visual_pr8.js`: два процентных ряда создают
  две пунктирные линии и две бледные подписи; последняя промежуточная
  фактическая точка не рендерится. При недоступности показывается
  причина, при завершённом месяце дополнительной прогнозной точки нет.
- `tests/test_kpi_chart_dialog_step7.js`: выбор метода KPI вызывает
  повторную подготовку именно этого графика и отображает разъяснение.
- `tests/test_step9_browser_offline.js`: открывает диалог настоящего
  объединённого HTML на встроенной базе, сравнивает forecast из
  Report Service с фактически отображёнными SVG-точками. Это закрывает
  пробел сквозной проверки, который позволял проходить CI при
  несоответствии цифр и вида графика.

## Ограничения

Пунктир показывается только для вычислимого месячного прогноза, не для
любого числа в последнем столбце. Если загружены не все события,
предварительный прогноз по последней наблюдаемой дате не удостоверяет
полноту корпоративной статистики; в подсказках этот статус сохраняется.
