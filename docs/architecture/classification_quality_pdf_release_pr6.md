# PR 6 — PDF-отчёт с двумя показателями качества классификации

## Назначение

Экспорт текущего **Report Snapshot** в автономный PDF без дополнительной загрузки данных или пересчёта KPI. PDF и веб-дашборд используют одни и те же значения, месяцы, фильтры и состояния доступности.

## Что включено

1. В блоке ключевых показателей идут рядом:
   - «Качество классификации — общее» (`classification_quality`);
   - «Качество классификации ЦГПС» (`classification_quality_cgps`).
2. Сохранён первоначальный график ВБР/SLA/общего качества. Его линии больше не соединяются через периоды, по которым значения отсутствуют.
3. Добавлен самостоятельный график **общего качества и качества ЦГПС** по одной шкале 0–100%, рассчитанный по `snapshot.series.monthly`. Пропущенные месяцы не интерполируются; `mb-coverage-unknown` подписывается, но не становится нулевым значением.
4. Добавлена отдельная читабельная часть «Качество классификации: состав расчёта»: четыре компонента A/B/C/D, числитель, знаменатель, процент или «—», основные правила включения.
5. Для ЦГПС дополнительно выводятся счётчики **«Нет в МБ»**, **«Нет данных МБ»**, **RITM иных инициаторов**. Когда охват МБ не подтверждён, итоговый процент не выдаётся, а причина недоступности поясняется.
6. Прежние KPI, трудозатраты, Problem Management и реестр источников отчёта остаются на своих местах.

## Методика

**Общий показатель:**
`A / (A+B+C+D) × 100%`, категории:
A = INC без изм; B = INC с исправлением;
C = INC не классифицирован; D = RITM вместо INC.
Обращения учитываются независимо от инициатора и наличия в МБ.

**ЦГПС:**
`A_МБ / (A_МБ+B_МБ+C_МБ+D_ЦГПС,МБ) × 100%`.
Для INC группа инициаторов не ограничена; для ошибочного RITM должна быть группа ЦГПС. Связь — по номеру обращения ITSM Сириус с актуальными задачами МБ. Состояние «Нет данных МБ» означает недоступный Dataset МБ и не приравнивается к «Нет в МБ» (номер не найден в загруженном Dataset без проверки дат). Для RITM пустая группа инициаторов исключается отдельно; обращения без номера ITSM также исключаются с диагностикой. Методика расчёта в PDF не реализована заново: выводятся готовые компоненты и результат Calculator.

Месяц определяется датой выполнения либо резервной датой закрытия; значения по нескольким месяцам считаются отношением сумм, не средним процентов.

## Технические гарантии

- Источник данных PDF — переданный снимок; прямых обращений к SQLite, ITSM Dataset, Mobile Brigade Dataset или калькулятору в PDF Renderer нет.
- PDF Renderer `1.1.0`. Изменение месячных данных качества классификации влияет на fingerprint файла даже при неизменном KPI выбранного месяца.
- В PDF используется нативный браузерный canvas/JPEG-пакет с кириллическими заголовками (как в прежней реализации); внешние библиотеки и сеть не требуются.
- Старые снимки без ЦГПС экспортируются без вымышленных значений/компонентов.
- Внутренние PDF-страницы формируются с автоматическим переносом и нумерацией.

## Критерии приёмки

- Общий KPI = 90%; ЦГПС = 90/95 ≈ 94,74% на согласованном контрольном примере.
- У ЦГПС в августе «Нет данных МБ», при наличии июльского и сентябрьского значений: две точки, без линии через август и без нуля.
- В PDF выведены обе карточки, категории A/B/C/D, источники, месяц, счётчики отсутствия номера в МБ, недоступности Dataset, RITM иных/неустановленных групп и пустого номера ITSM.
- При `mb-coverage-unknown`: только «—» вместо итогового процента и отдельное пояснение причины.
- Legacy Report Snapshot без ЦГПС не ломает экспорт.
- Полный CI: формулы и регрессии остальных KPI, тест PDF и офлайн-сборки, SQLite round-trip, автономный Chromium.

Формулировки: «ITSM Сириус», «в рамках деятельности ЦГПС». Термин «премиальный» не используется. В паспортах KPI сохраняются существующие пять разделов ВБР/КТГ.
