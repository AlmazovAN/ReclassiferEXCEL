# PR-2 — KPI Definition V2

Статус: технический контракт, не утверждённая производственная методика.

## Назначение
Расширяемая, неизменяемая спецификация показателей поверх существующих KPI Catalog и Calculation Contract. PR-2 только описывает возможности, не пересчитывает KPI и не изменяет интерфейс.

## Состав определения

| Раздел | Что описывает |
|---|---|
| identity | Идентификатор, категория, видимость |
| measurement | Тип расчёта (текущие coefficient, ratio, sum; зарезервированы count, custom; unconfigured для заготовок), единица |
| calculator | Действующий обработчик, версия формулы, ссылка на V1 Contract |
| data | Семантические поля источников, фильтры и период |
| components | Именованные компоненты Result.components |
| relatedMetrics | Дополнительные метрики, пока defined-not-connected |
| forecast | Существующая прогнозная политика и поддерживаемые методы |
| presentation | Текущие карточка, паспорт, линейный SVG и PDF |

### API

Сохраняются Catalog.version = 1.0.0 и методы get(), list(), getCalculation(). Добавлены definitionSchemaVersion = 2.0.0, getV2(kpiId) и listV2(options). Все записи и вложенные массивы неизменяемые.

### Прогнозирование

- VBR и KTG: reporting-month-components, готовый прогноз компонентов незавершённого месяца.
- Общая, АВР, ТО и корректирующая трудоёмкость: reporting-month-volume, прогноз абсолютного объёма.
- Остальные семь рассчитываемых KPI: historical-next-month; общий исторический алгоритм не равен прогнозу завершения отчётного месяца.
- Шесть заготовок: none; нет чисел, формул и подключённых алгоритмов.

Список forecast.methodIds описывает известные алгоритмы, но не включает их в UI. Выбор индивидуальной модели и синхронизация с паспортом относятся к PR-4 и PR-5.

### Обратная совместимость

Не меняются действующие формулы, обработчики, источники, фильтры, Snapshot, цвета и линии SVG, маркеры факта, прогнозные пунктиры, паспорт и PDF. Показатель avr_share остаётся в каталоге без отдельной карточки. Нет новых целей и утверждённых методик.

### Дальнейшие PR

PR-3 унифицирует визуализацию компонентов. PR-4 подключает реестр стратегий прогноза. PR-5 добавляет выбор модели в паспорт. PR-6 обеспечивает регистрацию простых новых KPI через декларацию и подключение общего UI. PR-7 проверяет это на новых показателях.

**Ограничение:** в PR-2 новые KPI ещё не создаются одной декларацией. Авторитетным источником остаются действующие Calculation Contract и Calculator, без дублирования исполняемых формул.
