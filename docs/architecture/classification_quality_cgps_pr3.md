# PR 3 — качество классификации ЦГПС

## Назначение
Отдельный показатель качества классификации в рамках деятельности ЦГПС.
Техническая информация о неисправностях должна соответствовать фактически
выявленным неисправностям и выполненным работам. Специалисты ЦГПС
непосредственно выполняют диагностику и восстановление и фиксируют
сведения об обстоятельствах отказа. Инженер по надёжности сопоставляет
текстовые описания работ и выбранные значения классификатора.

Проверка наличия заявки в МБ отделяет обращения, по которым работы
зарегистрированы в Мобильных бригадах, от остальных обращений ITSM Сириус.
Это не проверка наименования оборудования, и не фильтр `Открыл=Интеграция с МБ`.

## Формула
```
Q_ЦГПС = A_МБ / (A_МБ + B_МБ + C_МБ + D_ЦГПС_МБ) × 100 %
```

Где A — «INC без изм», B — «INC с исправлением», C — «INC не
классифицирован» (все группы инициаторов, если связь с МБ подтверждена),
D — «RITM вместо INC» **только** группы инициаторов ЦГПС, если связь
с МБ подтверждена.

Все четыре категории отбираются по расчётному месяцу: дата выполнения
приоритетна; если она отсутствует или непригодна, дата закрытия.
При выборе диапазона суммируются компоненты, а не проценты.

### Сопоставление
- ITSM Сириус: `itsm_data.number`.
- МБ: `mobile_brigade_data.request`.
- Используется общий модуль `ReclassifierItsmMbPresence`, индекс номеров
  собирается **один раз** на текущий набор данных МБ.
- Несколько задач МБ на один номер ITSM не дублируют обращение.
- Сохранённая в ITSM колонка `mbPresence` — снимок для человека, а не
  источник правила включения в данный показатель.
- Используется `initiatorGroup` — расчётное поле ITSM Handler, а не
  `openedBy`; для категорий INC группа не ограничивается.
- Кэш подготовки и расчёта сбрасывается при изменении Dataset ITSM или МБ.

### «Нет в МБ» и «Нет данных МБ»
- Подтверждённое «Нет в МБ»: обращение исключается из обеих частей формулы;
  количество фиксируется в диагностике.
- «Нет данных МБ»: Dataset МБ не загружен или недоступен. Для
  затронутого фильтра и периода итоговая оценка **не публикуется**:
  `no-data / mb-coverage-unknown`. Отсутствие номера в загруженном
  наборе МБ трактуется как «Нет в МБ» независимо от даты создания.
  Неполная выгрузка может исказить состав включённых обращений.
- Исключённые `RITM вместо INC` иных инициаторов не входят ни в числитель,
  ни в знаменатель и подсчитываются отдельно. Пустая/неустановленная
  группа инициаторов — отдельный счётчик, также не ЦГПС. Пустой номер
  ITSM исключается с диагностикой, а не трактуется как отсутствие в МБ.
- Для периода без подходящих обращений возвращается
  `no-data / classification-denominator-zero`.

## Компоненты результата
`classificationSuccessCount`, `classificationFailureCount`,
`classificationTotalCount`, 4 категориальных счётчика A/B/C/D,
`excludedNoMbCount`, `unknownMbCoverageCount`,
`excludedOtherInitiatorRitmCount`, `excludedUnknownInitiatorRitmCount`,
`excludedMissingRequestCount`.

**Актуализация PR 7:** проверка наличия в МБ выполняется **только по ID**,
без временных ограничений, а пустая группа инициаторов и пустой номер
ITSM учитываются отдельными диагностическими счётчиками. 

## Границы работ
- PR 3 создаёт самостоятельные KPI Facts/Preparation/Calculator/Contract,
  отчётный KPI Result, динамику расчётных точек, трассировку, диагностический
  результат и методику в существующих элементах паспорта.
- **Отдельная карточка дашборда и окончательная компоновка графиков — PR 4.**
  До этого показатель зарегистрирован в Каталоге как рассчитываемый,
  но не добавлен в перечень видимых карточек.
- Формула общего качества не меняется.
- Структуру паспорта сохранять как ВБР/КТГ: без новых разделов и
  без исключённого пользователем примера.
- Терминология: «ITSM Сириус», «В данный показатель…»,
  «в рамках деятельности ЦГПС».

## Контрольный пример
Из 100 обращений: 90 правильных INC, 5 неверных RITM группы ЦГПС,
5 неверных RITM других инициаторов. Если все найдены в МБ,
качество ЦГПС = 90 / 95 × 100 = 94,74 %, общее качество — 90 %.
