# PR-3. Унифицированное представление компонентов KPI

Статус: интерфейсная доработка действующего расчётного контура. Утверждённые методики и исходные данные не изменяются.

## Основная задача

Избавиться от безымянных блоков «Компонент 1 / Компонент 2» для KPI с обычной формулой. Названия, роли, единицы измерения компонентов должны определяться по единой спецификации KPI Definition V2, добавленной в PR-2, и фактическим Result.components, полученным в Report Snapshot.

## Контракт

Общий read-only API: `ReclassifierKpiCatalog.projectComponents(kpiId, result)`. Он возвращает:

| Свойство | Назначение |
|---|---|
| kind | Тип KPI, без изменения исходной формулы |
| items | Компоненты с ключом, названием, единицей, ролью, значением и состоянием |
| numerator, denominator | Реальные именованные операнды процентных KPI |
| primary | Основной компонент абсолютной суммы |
| requiredComplete | Присутствуют ли обязательные составляющие |
| canDisplayFormula | Факт рассчитан и доступна достаточная информация для отображения |
| observedValue | Только фактический Result.value, без экстраполяции |
| reason | Исходная причина недоступности расчёта |

Правила: нуль считается действительным значением; null, undefined, строка, NaN и Infinity не преобразуются в нуль. Отсутствующий или недоступный результат не становится рассчитанным. API замораживает возвращаемые данные, не изменяет исходный Result и не выполняет арифметику.

## Подключение к интерфейсу

- В общем паспорте на вкладке «Обзор» компонент показывается под понятным названием с фактической единицей, исходным ключом Result.components и ролью (числитель/знаменатель/другой).
- Все исходные компоненты остаются доступны. Если Calculator вернул дополнительный ключ, ещё не описанный в V2, он сохраняется в диагностической таблице под исходным именем, без придуманной семантики.
- В модальном графике стандартных долей (SLA, доля АВР, реактивная деятельность, относительный охват PRB) выводится прежняя плиточная дробь с корректными названиями двух частей и подписью «× 100%».
- Для абсолютных KPI (трудоёмкость и абсолютный охват PRB) выводится основная фактическая составляющая, а прочие — в сворачиваемом блоке без искусственного усреднения или суммирования.
- Сложные формулы ВБР, КТГ и категорий A/B/C/D качества классификации намеренно продолжают использовать существующие специализированные HTML-блоки. При необходимости их можно перенести на общий математический шаблон отдельным PR, но не ценой изменения визуального языка.
- У части трудовых KPI поле `taskCount` относится ко всем задачам выбранного среза, даже когда `laborHours` отфильтровано по виду. Подпись остаётся «Все задачи выбранного среза», а не «Количество АВР/ТО».

## Неприкосновенные элементы

Расчётные формулы, Calculator, Preparation, фильтры, Dataset, Report Snapshot, прогнозные стратегии, временные диапазоны, линии и точки графика, цвета, `stroke-dasharray="5 4"`, значение последнего факта и его отдельное отношение к прогнозной точке **не изменены**. PDF продолжает читать существующий Snapshot; его оформление не перерабатывается.
