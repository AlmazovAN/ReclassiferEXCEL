# Этап 3/4: источники, условия и последовательность расчёта

## Цель
Паспорт KPI читается в порядке: определение → формула → как рассчитывается → из каких источников → фактический результат. Техническая спецификация остаётся доступной по запросу.

## Настоящие заголовки источников

Заголовки для `itsm_data` берутся непосредственно из активного `ReclassifierFieldRegistry.get('itsm_data', field).sourceLabel`, то есть из схемы выгрузки, зарегистрированной модулем ITSM. Например, `completedAt` → «Дата выполнения обращения», `closedAt` → «Дата закрытия», `classificationQuality` → «Кач классификации». Для столбцов Full Dataset, указанных явно в Calculation Contract (например, `slaOverdue` — «Просрочен по разрешению»), сохраняется согласованный заголовок контракта. Если заголовок неизвестен, отображается «Не установлено в схеме ITSM»: внутренний ключ **не выдаётся** за физическую колонку.

Сводный реестр `combined`: колонки относятся к уже сформированному Equipment_Combined; `meta.freshness` отдельно показано как **метаданные Dataset**, а не колонка Excel.

Для `mobile_brigade_data` используется согласованная схема отчёта МБ: «Фактическая дата», «Итог Новый тип задач», «Фактические трудозатраты», «Заявка», «Участок» и другие. `recordKey`/`laborState` обозначены как производные поля, `laborHours` — как нормализованное значение исходных фактических трудозатрат.

Все имена проходят HTML-экранирование. Поля источника не меняются в хранилище, импорте и Calculator.

## Понятная методика

Новый раздел «Как рассчитывается показатель» создаётся из **существующего Calculation Contract**, а не из отдельного неофициального набора правил. Он содержит:
- список источников и основания определения месяца;
- условия отбора `facts` с исходными заголовками;
- доступные разрезы и фильтры выбранного отчёта;
- пронумерованную цепочку из `steps`, включая операции подсчёта, суммы, деления, вычитания и умножения.

Это **описание**, а не фактическая трасса: для измеренных количеств, отборов, промежуточных компонентов и ревизий применяется существующая кнопка «Показать расчёт».

## Скрываемые подробности

Каждый источник отображается кратко, а технические поля, колонки, ревизия, контрольная сумма — в его собственном `<details>`. Все подробные таблицы JOIN, предикаты, обработчики, агрегации и правила периодов собраны в общий `<details>` с заголовком «Техническая документация». Паспорта и расчёты не раздваиваются: у страницы и диалогового окна один `ReclassifierKpiPassportView`.

## Проверки
`tests/test_kpi_passport_lineage_step3.js` проверяет реальные заголовки ITSM через Field Registry, схему МБ, метаданные Equipment, все 18 паспортов и отсутствие вымышленных методик. Регрессии страницы и модального паспорта, сборка HTML и offline Chromium выполняются в GitHub Actions.

Не менялись Dataset, арифметика Calculator, KPI Result, Report Snapshot, PDF, прогноз, исторические данные и трассировка.
