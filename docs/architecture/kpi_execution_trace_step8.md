# KPI Runtime Execution Trace — шаг 8 из 9

## Что отображается

Раздел **«Показать расчёт»** добавлен к каждому KPI в обоих паспортах: отдельная страница и модальное окно.

Раздел использует реальные события текущего выполнения Calculator:

- объём Dataset, доступность, ревизия, хеш, дата источника;
- подготовленные компонентные таблицы и количество **агрегированных групп**;
- фактические фильтры периода, рудника, класса оборудования;
- количество строк до/после каждого реально применённого фильтра и исключённые группы;
- отбор видов работ для числителя трудозатрат: количество выбранных групп и действительная сумма часов;
- PRB: количество выбранных задач, однозначно связанных и несвязанных с PRB, плюс суммарная диагностика соединений Preparation;
- компоненты и итог из фактического KPI Result после контроля источников;
- причины недоступности, когда выполнить расчёт нельзя.

## Принцип инструмента

    Runtime Repository → Source Facts → Preparation → Calculator
        → selectRows() / typeHours() / prb.components()
        → trace events for each KPI
        → Results + source guard → trace.finalize(Results)
        → one immutable Report Snapshot.executionTrace
        → shared Passport View: «Показать расчёт»

Сбор событий происходит **в том же проходе Calculator**, а не вторым расчётом и не вычислением из текстовых формул Каталога. Поддерживается опциональный сбор через `request.trace` и `query.audit`; вызовы без инструмента сохраняют прежнее поведение.

Показатели из `KPI Result.components` и итог берутся из реально посчитанных значений. При отсутствии Dataset итоговая трасса помечается `source-guarded`. Для неподключённого KPI — `not-implemented`, для раннего выхода Calculator без отборов — `no-selection-executed`.

## Границы доказательности

| Элемент | Реальный смысл |
|---|---|
| Исходных строк Dataset | Количество записей во всём наборе, а не только в текущем месяце |
| Подготовленные строки | Количество компонентных сгруппированных строк, а не исходных ITSM/МБ задач |
| Отбор периода и измерений | Действительные inputRows/outputRows/excludedRows при выполнении selectRows |
| АВР, корректирующие работы | Число выбранных компонентных групп и сумма часов при выполнении typeHours |
| PRB | Счётчики отобранных задач и связей при выполнении components; полная диагностика JOIN относится ко всему подготовленному Dataset |
| Арифметика | Фактические компоненты KPI Result и итоговая величина Calculator |
| Catalog Steps | Декларация методики, НЕ журнал реального исполнения |

**Важно:** без сохранения индивидуального следа каждой исходной ITSM/МБ записи нельзя честно показать построчные решения фильтров после агрегирования. Такие данные **не выдумываются**. Содержимое паспорта прямо поясняет ограничения.

Сохраняются только агрегированные диагностические данные и поля фильтров, без текста заявок или личной информации. HTML-экранирование обязательно.

## Реализация

- `src/js/kpi/execution_trace.js` — `createCollector({prepared,sources,query})`, `forKpi(id)`, `finalize(results)`; версия 1.0.0; immutable результат для 18 KPI.
- `src/js/kpi/calculator/common.js` — инструментированный `selectRows()` с действительными поэтапными счётчиками.
- `src/js/kpi/calculator/index.js` — необязательный audit по ID показателя в том же вычислении.
- `src/js/kpi/calculator/labor/calculate.js` — реальный подсчёт подмножеств типов работ.
- `src/js/kpi/calculator/problem_management/calculate.js` — реальный выбранный набор PRB.
- `src/js/kpi/calculator/vbr/calculate.js` — отдельные наблюдения отказов и Equipment.
- `src/js/app/reliability_report_service.js` — трасса только текущего расчёта, не месячной динамики.
- `src/js/kpi/report_snapshot.js` — опциональное поле `executionTrace`; старые WEB/PDF контракты сохранены.
- `src/js/kpi/passport_view.js` — один renderer для двух интерфейсов.

## Тестирование

- `tests/test_kpi_execution_trace.js` — реальное исполнение фильтров, исключения, ревизии и неизменность результатов.
- `tests/test_reliability_report_service.js` — реальные SLA, ВБР, трудозатраты, PRB, защита при отсутствующем Dataset и HTML-паспорт.
- `tests/test_kpi_passport_view.js` — старый Snapshot без runtime-трассы честно показывает её недоступность.
- GitHub Actions: полный регресс, автономный HTML, SQLite WASM, Chromium.
