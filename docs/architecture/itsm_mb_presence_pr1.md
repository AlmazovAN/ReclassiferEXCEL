# PR 1 — наличие обращения ITSM Сириус в Мобильных бригадах

## Назначение
Поле **«Наличие заявки в МБ»** отвечает на вопрос: найден ли номер обращения из ITSM Сириус
среди номеров заявок, связанных с задачами Мобильных бригад. Это признак существования
связи между обращением и задачами, а **не** наименование оборудования и не подтверждение
факта передачи через интеграцию.

## Источники и связь
- ITSM Dataset: `number` («Номер»).
- Mobile Brigade Dataset: `request` («Заявка»).
- Сопоставление: нормализация пробелов/регистра и точное равенство номера.
- При нескольких задачах МБ на одну заявку результат один: **«Есть в МБ»**.
- Поле `equipmentName` («НаименованиеТехники») остаётся служебным обогащением
  оборудования; оно не используется для определения наличия заявки.

## Значения
| Значение | Значение признака |
| --- | --- |
| Есть в МБ | Соответствующий номер найден хотя бы у одной задачи МБ |
| Нет в МБ | Номер не найден в текущем загруженном Dataset МБ, независимо от дат |
| Нет данных МБ | Невозможно проверить: Dataset МБ отсутствует или недоступен либо номер обращения ITSM пустой |

Для определения наличия **никакие даты не используются**. В этом признаке «Нет в МБ» означает отсутствие номера в загруженном Dataset, а не подтверждение отсутствия во всей корпоративной системе. Неполная выгрузка способна пропустить существующие заявки. Для KPI ЦГПС пустые номера ITSM исключаются отдельно и подсчитываются в диагностике; отсутствие самого Dataset МБ делает значение недоступным.

## Где хранится и как обновляется
- Расчётный Excel ITSM: новый столбец BJ; действующие 34 колонки AB:BI не меняются.
- `itsm_data`: 52-е поле `mbPresence`, schema 1.2.0; наименование из Field Registry.
  Историческому новому полю присваивается **«Нет данных МБ»**, не выдумывается связь.
- SQLite DB Schema 4 переносит существующие строки v1.1.0 на v1.2.0 и не меняет
  прежние поля.
- Сохранённый в ITSM признак — **снимок на момент обработки**. При замене данных МБ
  он может устареть. Для показателя качества классификации ЦГПС следует запрашивать
  **актуальную** связь из текущих Dataset через `ReclassifierItsmMbPresence`,
  пересчитывая после обновлений ITSM/МБ. Не использовать сохранённое значение как
  безусловный источник истины.

## Правила PR 7 (актуальная редакция)

- Совпадение номера — учитывать заявку в KPI ЦГПС без проверки даты создания и дат выгрузки.
- Нет совпадения — исключить, даже если метаданные свежести отсутствуют.
- МБ недоступны — не публиковать KPI ЦГПС; если нет номера ITSM — исключить с отдельным счётчиком.
- RITM с пустой расчётной группой инициаторов не считать заявкой ЦГПС, учитывать отдельно от RITM других групп.

## Дальнейшее внедрение
PR 2 обновляет общий показатель и даты; PR 3 использует живое сопоставление
для качества классификации ЦГПС. Паспорта двух KPI должны использовать существующую
структуру разделов ВБР/КТГ, без дополнительных разделов.

Формулировки для паспортов: «ITSM Сириус», «В данный показатель включаются только
обращения…», «в рамках деятельности ЦГПС». Слово «премиальный» не использовать.
Дополнительный пример с кабелем и антенной не добавлять.
