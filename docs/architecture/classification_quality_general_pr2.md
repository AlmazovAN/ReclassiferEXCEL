# PR 2 — общий показатель качества классификации

## Назначение
Общий показатель качества классификации оценивает долю обращений ITSM Сириус, у которых
классификация INC подтверждена без исправлений, среди всех обращений,
для которых установлена одна из четырёх учитываемых категорий.

## Формула
**Qобщ = A / (A + B + C + D) × 100 %.**

| Обозначение | Категория в ITSM Dataset | Включение |
| --- | --- | --- |
| A | «INC без изм» | Числитель и знаменатель |
| B | «INC с исправлением» | Только знаменатель |
| C | «INC не классифицирован» | Только знаменатель |
| D | «RITM вместо INC» | Только знаменатель |

В данный показатель включаются только обращения с одной из категорий A/B/C/D
и определённым месяцем выполнения или закрытия. «RITM без изм» и иные
категории не входят в знаменатель. Если знаменатель равен нулю,
результат недоступен (а не 0 или 100 %).

**Общий** показатель не зависит от принадлежности инициатора к ЦГПС и наличия
задачи в Мобильных бригадах. Все «RITM вместо INC» учитываются независимо
от группы инициатора. «INC без изм» входит в числитель, даже если в МБ
не найдена соответствующая заявка.

## Период и фильтры
- Основной месяц учёта — **дата выполнения** (`completedAt`).
- Если дата выполнения отсутствует или не распознаётся, используется
  **дата закрытия** (`closedAt`).
- Если отсутствуют обе пригодные даты, обращение не входит в период и
  учитывается в диагностике.
- При выполнении в сентябре и закрытии в октябре обращение относится к сентябрю.
- Для диапазона месяцев сначала суммируются A/B/C/D, затем рассчитывается
  общий процент. Среднее арифметическое месячных процентов не используется.
- Поддерживаются существующие фильтры: филиал, рудник, класс, тип,
  наименование оборудования. Общий показатель не фильтруется по МБ и инициатору.

## Техническая реализация
- `ReclassifierKpiSourceFacts` нормализует категорию в `classificationCode`: A/B/C/D.
- `ReclassifierKpiPrepareClassification` считает четыре компонента,
  агрегируя данные по выбранному месяцу и существующим измерениям.
- `ReclassifierKpiCalculateClassificationQuality` возвращает значение,
  три базовые величины и детализацию A/B/C/D.
- Диагностика: `notApplicableRows`, `includedRowsWithoutEventDate`,
  `countedUsingCompletionDate`, `countedUsingCloseDate`.
- `KPI_Source` получает такую же периодизацию для
  `ClassificationSuccessCount` и `ClassificationTotalCount`. При этом
  его прежние 22 поля сохранены, а SLA по-прежнему учитывается по закрытию.
  Persisted KPI_Source пересчитывается при обработке ITSM или накопительном
  UPSERT; ранее сохранённые агрегаты не исправляются самостоятельно
  при одном только обновлении приложения.

## Контрольные сценарии
1. 90 «INC без изм» + 5 «RITM вместо INC» ЦГПС + 5 «RITM вместо INC» иных
   инициаторов: **90 %**.
2. «RITM без изм» не изменяет числитель и знаменатель.
3. «INC без изм», отсутствующий в МБ, остаётся в общем показателе.
4. Дата выполнения 29.09 и закрытия 01.10: учёт в сентябре.
5. При отсутствии/ошибке даты выполнения используется корректная дата закрытия.
6. Без обеих дат обращение исключается с диагностикой; без знаменателя
   показатель недоступен.

Паспорта KPI сохраняют действующую структуру ВБР/КТГ, без новых разделов.
Отдельный показатель в рамках деятельности ЦГПС относится к следующему PR.
