# PR 5 — паспорта качества классификации

## Цель и состав

Привести паспорта **«Качество классификации — общее»** и
**«Качество классификации ЦГПС»** к единой структуре действующих паспортов
ВБР и КТГ. Других разделов не создавать.

Оба паспорта используют один и тот же отрисовщик и одну последовательность:

1. Описание и назначение
2. Формула расчёта
3. Как рассчитывается показатель
4. Техническая документация
5. Прогноз и контроль качества

В блоке «Техническая документация» остаются существующие раскрываемые
детали: источники и колонки, связи, фильтры, последовательность операций,
агрегирование, периоды, реальная трассировка. Никаких самостоятельных
разделов «Источники информации / Содержание» или дополнительных
презентационных таблиц нет.

## Смысл результата

Качество классификации — доля обращений, для которых первоначальная
классификация ITSM Сириус подтверждена при инженерной проверке.
Проверяющий сопоставляет выбранный классификатор с описанием неисправности,
диагностикой и сведениями о выполненных работах. **Сам числовой KPI**
не читает и не интерпретирует текст; он агрегирует уже присвоенную
категорию `classificationQuality` («Кач классификации»).

### Общее качество

`Q = A / (A + B + C + D) × 100 %`

- A — INC без изм
- B — INC с исправлением
- C — INC не классифицирован
- D — RITM вместо INC

Все четыре категории включаются независимо от инициатора и наличия
в Мобильных бригадах. «RITM без изм» исключается.

### Качество ЦГПС

`Q = A_МБ / (A_МБ + B_МБ + C_МБ + D_ЦГПС_МБ) × 100 %`

В данный показатель включаются только обращения с подтверждённой связью
с МБ в рамках деятельности ЦГПС. Для всех INC группы инициаторов не
ограничиваются; D учитывается только при группе «ЦГПС».

Подтверждение связи: нормализованное точное равенство
`itsm_data.number` и `mobile_brigade_data.request`.
Несколько задач по одному обращению не умножают его количество.
Наличие в МБ не устанавливает автора каждого текстового поля.
Признак `Открыл = Интеграция с МБ` не требуется.

**«Нет в МБ»** означает отсутствие номера в загруженном Dataset МБ и исключает заявку из KPI независимо от дат. **«Нет данных МБ»** означает отсутствие или недоступность самого Dataset МБ; итоговый процент не публикуется. Трассировка содержит исключения: номер не найден, Dataset недоступен, RITM других групп, RITM с пустой группой, обращение без номера ITSM. Пустая группа инициаторов для D не считается ЦГПС. Неполнота выгрузки МБ не может быть определена по датам и остаётся ограничением исходных данных.

## Временная основа

Оба KPI относятся к месяцу `completedAt` («Дата выполнения обращения»),
при его отсутствии/невалидности — `closedAt` («Дата закрытия»).
Без обеих пригодных дат обращение исключается из периода.
При объединении месяцев числитель и знаменатель суммируются
отдельно, среднее месячных процентов не берётся.

## Источники и проверяемость

ITSM Сириус: исходные и скорректированные позиции классификатора,
`classificationQuality`, номер, даты, пояснения, `initiatorGroup`,
его исходное `openedBy` (для ЦГПС).

Мобильные бригады: `request` и устойчивый ключ задачи;
достаточно подтверждённого наличия хотя бы одной задачи.
Текстовые и диагностические исходные поля отображаются как
**контекст инженерной проверки**, не объявляются автоматически
проанализированными калькулятором.

Паспорта используются на дашборде и странице паспортов через общий
`ReclassifierKpiPassportView`. Математические блоки формируются
локально в MathML, согласованном с неизменённой сигнатурой Calculator;
примеры **условные**, не подменяют фактический результат.

## Границы PR

- Только методическое содержание, отображение и диагностическая
  трассировка паспортов.
- Без изменения формул KPI, алгоритма автореклассификации,
  входных Dataset, порогов и статуса утверждения методики.
- PDF отчёта остаётся задачей PR 6.
- Используемые формулировки: «ITSM Сириус», «В данный показатель…»,
  «в рамках деятельности ЦГПС». Термин «премиальный» не используется.
- Исключённый пользователем иллюстративный пример с повреждением кабеля
  не добавляется; числовой пример 90/95 сохранён.
