# Hotfix — видимость прогноза на графиках INC и трудоёмкости

## Выявленный дефект

Ранее `buildOperationalChartData()` возвращал объект месячного ряда
**без поля `forecast`**, если отчётный месяц не установлен или не совпадает
с видимым. SVG просто показывал накопленный факт (например, сентябрьскую
трудоёмкость 874 чел.-ч), не объясняя отсутствие пунктира.

Даже при наличии `forecast.dataState='insufficient'` график не объяснял
причину. Пользователь видел ситуацию как неисправность отрисовки.

## Исправлено

- Месячные операционные ряды INC и трудоёмкости **всегда** получают
  `series[].forecast` со статусом, причиной и источником; числовой прогноз
  создаётся только при достаточных подтверждённых данных.
- Для неготового прогноза рядом с графиком показывается причина:
  неподтверждённая выгрузка, завершённый месяц, неподходящий период,
  недостаточная история, неполное покрытие, проблемы с компонентами и т. д.
- Для неподтверждённого источника доступен переход в раздел
  «Покрытие данных ITSM и МБ», с открытием нужной секции.
- В режиме «М» можно выбрать один из **уже существующих** методов
  Forecast Engine: `linear-trend`, `last-value`,
  `observed-run-rate`. Изменение метода обновляет прогноз, но не
  фактические точки графика.
- Для шкалы «Д»/«Н» объясняется, что прогноз существует только на
  уровне месяца.
- Правило PR-8 остаётся прежним: процентные KPI — только прогнозная
  точка, абсолютные метрики — накопленный факт и вертикальный пунктир
  к прогнозу того же месяца.

## Требования к подтверждению

Наличие событий в сентябре само по себе не подтверждает полноту сентября
или конкретного дня. Нельзя автоматически использовать последнюю дату
события, имя файла, дату запуска. Если интервал не подтверждён,
пунктир **не** рисуется, а интерфейс указывает причину и действие.

Если месяц завершён по подтверждённому интервалу, прогноз не нужен:
сентябрьская величина является итоговым фактом, а не незавершённой
месячной оценкой.

## Границы

Приложение работает на JavaScript. Этот дефект обусловлен логикой
`null/insufficient` и ранним возвратом без метаданных, а не
использованием JavaScript вместо TypeScript. Типы могут быть
дополнительно проверены `// @ts-check`/JSDoc без перевода монолитного
offline HTML на новую систему сборки.

Окончательная проверка на реальных выгрузках возможна только после
подтверждения пользователем интервала соответствующего Dataset.
