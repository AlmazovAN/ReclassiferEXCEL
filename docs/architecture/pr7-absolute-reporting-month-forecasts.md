# PR-7 — Прогнозирование абсолютных метрик

## Цель

Распространить проверенную схему PR-2/PR-3 прогнозирования **последнего
неполного отчётного месяца** на абсолютные объёмы:

- `inc` — число завершённых INC из ITSM, дата `completedAt`;
- `labor` — пригодная к расчёту трудоёмкость задач МБ, дата `factDate`;
- `total_labor`, `avr_labor`, `maintenance_labor`, `corrective_labor` —
  уже существующие результаты KPI Calculator по категориям трудоёмкости.

Для INC **не** используется `failureCount`: это только подтверждённые
отказы для ВБР, а метрика «Завершённые INC» включает завершённые
инциденты вне зависимости от решения об учёте отказа.

## Формула и модели

```
прогноз итога = факт на дату подтверждённой выгрузки
              + прогноз суточной интенсивности × оставшиеся дни
```

Метод `observed-run-rate` использует среднесуточный факт,
`last-value` — интенсивность предшествующего завершённого месяца,
`linear-trend` — тренд суточной интенсивности завершённых месяцев,
проверенный по MAE против `last-value` с возможным fallback.
Последние **8 последовательных завершённых календарных месяцев**
требуются для линейного тренда (6 обучающих + 2 проверочных);
отсутствующие/неполные месяцы не выдаются за нули.

Прогноз количества INC округляется до целого, исходная непрерывная
величина хранится в `rawProjectedValue`.
Прогноз человеко-часов остаётся дробным; форматирование и отображение
будут согласованы в PR-8.

## Источники и безопасность данных

Вход метода `predictReportingMetric()`:
`metricId`, `selectedMonth`, `reportingCoverage`, `current`,
`points`, `methodId`. На вход передаются **готовые месячные
показатели**, вычисленные существующей подготовкой и Calculator.
Исходные строки ITSM и МБ в Forecast Engine не попадают.

Для числового прогноза обязательны:

- совпадение `coverage.sourceId` с источником метрики;
- `coverageBasis='source-export-cutoff'`;
- `reportMonthStatus='incomplete'`;
- подтверждённый календарный период `coverageFrom/Through`;
- минимум 4 прошедших дня;
- валидные текущие данные и полная непрерывная история нужной модели.

Последняя дата события, текущее время, `loadedAt` и дата отчёта
**не подтверждают** конец выгрузки. При `unknown` прогноз имеет
`value:null` и причину `reporting-cutoff-unconfirmed`.
При `complete` выдаётся `report-month-complete`, без прогноза.

## Встраивание

- `src/js/kpi/forecast_engine.js` — версионированный реестр абсолютных
  метрик `REPORTING_VOLUME_METRICS` и чистая функция
  `predictReportingMetric`, результат типа
  `reporting-month-volume-nowcast`.
- `src/js/kpi/report_view_model.js` — прогнозы трудоёмкости отдельно
  от значения KPI в `series.monthly[].forecasts`,
  `kpiView.cards[].forecast` и `seriesById[].points[].forecast`.
- `src/js/app/reliability_report_service.js` — независимая восьмимесячная
  история для детальных KPI и месячных операционных графиков.
  `buildOperationalChartData('inc'|'labor','month',...)` возвращает
  `series[].forecast` рядом с `series[].points`.
  Проекция 1М/3М/1Г/Все не влияет на модель. Суточная/недельная
  детализация пока не меняется, её оформление — задача PR-8.
- Версии, фактическая и прогнозная величины, метод, MAE, интервал
  наблюдения и `sourceRevisions` сохраняются отдельно.

## Границы PR

Не изменяются KPI Calculator, формулы ВБР/КТГ, правила отнесения
INC/трудозатрат, исходные Dataset и визуальные стандарты графиков.
Отдельное отображение **факт + прогноз** для абсолютных метрик и
**прогноз вместо промежуточного факта** для процентов — PR-8.
Подтверждение границы экспорта в процессе загрузки реальных Dataset,
включая повторное открытие HTML, — PR-9.

## Приёмка

`tests/test_kpi_reporting_volume_forecast_pr7.js` проверяет
три метода, исходный факт, ошибку MAE и источник, февраль
високосного года, методики на разные классы трудоёмкости, отсутствие
подтверждённого интервала и Snapshot.
`tests/test_reliability_report_service.js` сравнивает прогнозы
1М/1Г и значения трудоёмкости в Calculator и операционных рядах.
Обязательна полная проверка GitHub Actions, включая автономный Chromium.
