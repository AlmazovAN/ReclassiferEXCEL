# Единый UI паспорта показателя

Статус: реализовано в приложении; методики KPI сохраняют исходные статусы, в том числе `draft`.
Изменение относится только к представлению. Сами формулы, фильтры и исходные наборы данных не меняются.

## Состав интерфейса

Страница «Паспорта KPI» и модальное окно на странице «Отчёт по надёжности»
вызывают одну функцию `ReclassifierKpiPassportView.renderContent(kpiId, options)`.

Для всех 19 записей каталога одинаково отображаются:

1. Шапка: категория, название, идентификатор, статус расчёта, версия и статус методики.
2. Сводка: текущее значение, утверждённая цель (если есть), состояние доступности.
3. Вкладка «Обзор»: назначение, текущий результат/источник, интерпретация и ограничения.
4. Вкладка «Методика»: визуальная формула, машинная формула/версия, правила отбора и последовательность расчёта.
5. Вкладка «Данные»: Dataset, реальные именования столбцов, ревизии, связи, фильтры, шаги, агрегация и время.
6. Вкладка «Динамика и контроль»: помесячный график, прогноз, факт трассировки и сведения о версиях.

Не реализованные KPI получают те же вкладки с явными сообщениями о недоступности;
формулы, данные, цели и результаты для них не подставляются.

## Источник истины

| Объект | Назначение |
|---|---|
| `ReclassifierKpiCatalog` | Определение, назначение, методика, исходные поля, формула, версия |
| `Report Snapshot.results[id]` | Факт, состояние, компоненты и версия исполненной формулы |
| `Report Snapshot.kpiView.cards[id]` | Значение/период/прогноз для текущего среза |
| `Report Snapshot.kpiView.seriesById[id]` | Рассчитанные месячные точки для мини-графика |
| `Report Snapshot.executionTrace.byKpi[id]` | Фактические события трассировки, а не описание правил |
| `Report Snapshot.sources` | Доступность, ревизии, хеши и свежесть Dataset |

Функция визуализации только читает эти объекты. Она не пересчитывает KPI,
не читает SQLite и не создаёт фиктивных событий. Отсутствующие месяцы разрывают
линию, не превращаются в нулевые показатели. График паспорта показывает
до 12 последних месяцев; полный интерактивный сравнительный график по-прежнему
находится в отчёте по надёжности.

## Управление состоянием

Общий `bindTabs(container, onSelect)` реализует вкладки с корректными
`role=tablist`, `role=tab`, `role=tabpanel`, `aria-selected` и
`hidden`. Работают мышь и клавиатура (стрелки, Home, End).
На странице паспортов выбранная вкладка сохраняется при асинхронной
подстановке фактического Snapshot; при выборе другого KPI открывается «Обзор».

Модальное окно и каталог используют идентичный HTML-шаблон и стили.
Права доступа к данным, экспорт PDF и старый Calculation Contract не изменены.
PDF продолжает использовать один готовый Report Snapshot без собственного
чтения Dataset/повторного расчёта, а не HTML-представление вкладок.

## Проверки

- `tests/test_kpi_passport_unified_ui.js`: все KPI имеют четыре вкладки и
  обязательные разделы; пропуск месяца даёт разрыв, отсутствие ряда — сообщение.
- `tests/test_kpi_passport_view.js`, `tests/test_kpi_passport_lineage_step3.js`,
  `tests/test_classification_quality_passports_pr5.js`: формулы, поля,
  специфические пояснения, ревизии и трассировка остались доступными.
- `tests/test_kpi_passports_page.js` и
  `tests/test_kpi_passport_dialog_step5.js`: один шаблон в двух точках UI.

Граница изменений: точные утверждённые цели, нормативы, владельцы методик и
методики незавершённых KPI не создаются автоматически.
