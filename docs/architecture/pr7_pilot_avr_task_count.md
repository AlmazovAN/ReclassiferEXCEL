# PR-7 — пилот тиражирования: количество задач АВР

## Статус и границы

**Расчётная метрика, методика — draft / not-assigned.** Не является утверждённым корпоративным KPI, целевой уровень не задан. Программный Reclassifier остаётся прототипом для аналитики, а не официальным источником отчётности.

PR-7 впервые активирует одну реальную декларацию в новом механизме PR-6: `avr_task_count` — «Количество задач АВР». Существовавшие 19 KPI сохранены, новая запись становится 20-й в каталоге и 14-й с подключённым Calculator. В отдельном UI-коде для нового показателя нет необходимости.

## Формула и подготовка

```text
Количество задач АВР = Σ taskCount
  где prepared family = labor / mobile_brigade_labor
  finalTaskType = «АВР»
  период = месяц действительной factDate
  фильтры = рудник, класс/тип/наименование оборудования
```

**Источник:** `mobile_brigade_data` (ИС «Мобильные бригады»).

**Поля исходной нормализации:** `recordKey` (идентификатор записи), `factDate` (дата выполнения), `site` (рудник), `finalTaskType` (итоговый вид работы), `equipmentPlacement` (размещение), `equipmentType`, `transport` / `equipmentUnit` (объект) и состояние трудоёмкости.

**Подготовленный счётчик:** `taskCount`. Подготовка `ReclassifierKpiPrepareLabor.prepare` увеличивает этот счётчик на 1 для каждой строки с действительной `factDate`. Таблица агрегирована: **нельзя** использовать количество сгруппированных строк вместо суммы `taskCount`.

Дополнительные диагностические компоненты, не включённые в формулу:
- `avrUsableTaskCount` — задачи АВР с пригодной трудоёмкостью;
- `avrUnusableTaskCount` — задачи АВР с непригодной трудоёмкостью.

Пригодность часов **не влияет** на `avrTaskCount`, поскольку число задач и трудоёмкость — разные показатели. Задача с нулевыми трудозатратами или без пригодного значения часов всё равно учитывается при правильном типе работы и дате.

### Разграничение результатов

- Учитываются **записи задач** МБ, а не уникальные INC Сириус, количество отказов или число единиц оборудования.
- Если Dataset содержит дубли записей, этот счётчик их не дедуплицирует. Для официального показателя потребовалось бы отдельно согласовать ключ уникальности и источник дедупликации.
- Запись без пригодной `factDate` не относится к месяцу; запись без итогового типа «АВР» не входит в числитель.
- **0** означает, что за выбранный срез найдены другие записи, но нет соответствующих строк АВР. При отсутствии подготовленных записей за месяц — `no-data`, при отсутствии подготовленного источника — `unavailable`. Нет имитации полного покрытия месяцев вне выгрузки.
- Дата фактического выполнения и итоговый тип работы — текущие семантические данные загруженной МБ, а не подтверждение независимой проверки правильности каждой записи.

## Прогноз

Из текущего Forecast Strategy Registry подключён только `historical-next-month`: `linear-trend`, `last-value` по истории с необходимой длиной/валидацией. Отсутствие достаточной истории = `insufficient`, численный прогноз не показывается.

**Не подключается** пунктир «ожидаемый итог незавершённого месяца» для этой новой метрики. Такой прогноз требует отдельно проверить правила достоверности среза МБ и полноты фактических задач АВР. В PR-7 существующие пунктиры ВБР/КТГ/трудозатрат не меняются.

## Автоматическое представление

Одна запись в `src/js/kpi/calculator/declarative.js` добавляет Calculator, Contract, Catalog, Definition V2, паспорт с методикой и источниками, карточку в группе «Трудозатраты», месячный график, исторический прогноз при достаточных данных и строку KPI в PDF. Карточка измеряется в штуках и не подменяет уже существующую трудоёмкость АВР в чел.-часах.

## Контроль качества и трассировка

`ReclassifierKpiDeclarative.calculate` фиксирует для каждого компонента реальное количество подготовленных строк **до** и **после** фильтра `finalTaskType='АВР'`, а также `sumField` и `sumValue`. Audit становится частью проверяемого `executionTrace` отчёта без изменения способа записи самого Snapshot.

Числовые проверки:
- 3 задачи АВР: две с пригодными часами (включая ноль) и одна с непригодными часами → **3 шт.**, трудоёмкость АВР при этом **4 чел.-ч**;
- дата, рудник и класс оборудования фильтруются независимо;
- 0 / no-data / unavailable не смешиваются;
- отдельный тест существующего Reliability Report Service читает реальные подготовленные данные тестового источника, сверяет Snapshot, историю, диагностику, ревизию МБ и событийный аудит;
- полная регрессия PR-1–PR-6, PDF, SVG, SQLite и offline Chromium обязательна.

## Издержки добавления KPI

Для класса метрик COUNT/SUM/RATIO на уже доступной компонентной таблице **один декларативный объект** плюс отдельные проверочные тесты и описание методики. Новый специальный UI, CSS, PDF-рендерер и Calculator-модуль не требуются.

Ограничения сохраняются: более сложные KPI (уникальные сущности, пользовательские формулы, задержки инженерной реклассификации, агрегаты из нескольких источников, сейчас-каст) могут потребовать нового проверенного семейства подготовки и дополнительной стратегии прогнозирования. PR-6/7 не делает произвольные формулы или реклассификацию автоматическими.
