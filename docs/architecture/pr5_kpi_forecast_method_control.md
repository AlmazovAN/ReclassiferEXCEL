# PR-5 — выбор метода прогноза в едином паспорте KPI

## Цель

Добавить в общую вкладку «Динамика и контроль» выбор допустимого алгоритма прогноза для каждого из **13 реализованных** KPI, сохранив единый источник возможностей из Forecast Strategy Registry (PR-4) и действующие правила графиков (PR-1).

## Реализовано

- `ReclassifierKpiForecastEngine.forecastPreferences` — неизменяемый API управления временными предпочтениями пользователя: `methodsFor(kpiId)`, `get(kpiId)`, `set(kpiId,methodId,origin)`, `subscribe(listener)`. Состояние хранится **только в текущем сеансе**, не в Dataset/SQLite/localStorage, и не переносится в сохранённую HTML-копию.
- Для KPI выборы независимы. Для операционного графика `inc`/ `labor` настройки также независимы от KPI, на странице которого он открыт. Недопустимые методы отклоняются по списку методов реестра.
- В паспорте, доступном через модальное окно дашборда и отдельную страницу паспортов, расположен одинаковый `select`. При выборе формируется **аналитический сценарий прогноза** на основе уже рассчитанного Snapshot: повторно выполняется только прогноз, а не Calculator/подготовка источников.
- В общей диаграмме KPI и операционных графиках используется та же настройка по идентификатору KPI/метрики. В том числе переключатель метода доступен для абсолютных KPI трудоёмкости, поддерживающих прогноз итога месяца.
- Сохраняются выбранная вкладка паспорта, обновление UI после получения асинхронного Snapshot и выбранный метод при повторном открытии графика.
- «Автоматически» сбрасывает пользовательский выбор и снова показывает прогноз из исходного Snapshot. При отсутствии подтверждённого среза, обязательных компонентов либо достаточной истории сценарий корректно показывает недостаточность данных.

## Важное разграничение: что экспортируется

**Факт KPI и стандартный прогноз Snapshot неизменны.** Поскольку принятая модель Report Snapshot пока не включает отдельный пользовательский аналитический сценарий, ручной выбор в PR-5 **не подменяет и не экспортирует** прогноз Snapshot в PDF.

В паспорте ясно указано: «Сценарный прогноз», «не включён в Report Snapshot и PDF». Это предотвращает ситуацию, когда пользователь выбрал один метод для просмотра, а PDF показывает другое значение без объяснения.

Фиксация выбранных сценариев, их параметров, версии алгоритма и статуса при утверждении методики — отдельная последующая задача, требующая расширения версии Snapshot с сохранением неизменности истории и источников. В PR-5 она **не реализована**, и PDF остаётся полностью совместимым.

## Защищённые инварианты

- Формулы и численные значения Calculator не меняются.
- Прогнозная математика, MAE, методы, правила полноты и ограничения не меняются.
- Сплошные линии, последняя фактическая точка, вертикальный/наклонный пунктир прогнозной точки, цвета, SVG, легенда, подписи и масштаб не меняются.
- Старый прогноз Snapshot сохраняется для воспроизведения, контроля и PDF.
- Не вводятся «оптимистичные» прогнозы при отсутствии достоверных исходных данных.
- Индивидуальные корпоративные ML-алгоритмы по-прежнему не подключены. Интерфейс предлагает лишь реально зарегистрированные методы.

## Приёмка

`tests/test_kpi_passport_forecast_method_pr5.js` проверяет список методов для каждого семейства KPI, независимость настроек, делегированный обработчик паспорта, корректные числа по фактическим компонентам ВБР и трудоёмкости, исторический сценарий SLA, переключение «Автоматически», недоступные KPI, полную неизменность исходного Snapshot и синхронизацию с существующим контролом графика.

Прогоняются PR-1—PR-4, тесты исходных прогнозов, SVG, PDF и автономная HTML-сборка в Chromium без сети.
