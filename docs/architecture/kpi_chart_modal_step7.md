# Интерактивные графики KPI — шаг 7 из 9

Шаг 7 добавляет ко всем 17 карточкам отчёта кнопку «График», открывающую общее нативное модальное окно.

## Интерфейс

- Рудник: все рудники или отдельный из доступных, без изменения глобальных фильтров дашборда.
- Период: 3М, 6М, 1Г, Всё. Диапазон задаётся календарными месяцами и заканчивается выбранным месяцем отчёта.
- Месячные KPI Results: фактическая линия, разрывы там, где нет данных.
- Светлая толстая линия скользящего показателя с регулируемым окном 2–12 месяцев, начальное окно 4 месяца.
- Таблица значений за выбранный месяц по рудникам с отображением состояний недоступности.
- Диалог поддерживает крестик, Escape, фон и возврат фокуса на кнопку карточки.

## Методика скользящего показателя

**Процентные KPI**: сумма числителей за окно / сумма знаменателей за окно × 100. Пара компонентов определяется существующей декларацией операции DIVIDE в Calculation Contract, а числа поступают из KPI Result.components. Среднее месячных процентов не используется.

**Абсолютные KPI**: арифметическое среднее месячных значений KPI Result за полное окно. Поэтому для режима представления rolling изменено значение sum → average в Calculation Contract. Официальные формулы, Calculator и способ получения многомесячного общего объёма не меняются.

Окно обязано быть календарно непрерывным, без пропусков и недоступных значений. Иначе точка не рассчитывается. Скользящий ВБР остаётся недоступным до появления исторического парка оборудования. Скользящий показатель — не прогноз, прогнозирование остаётся задачей шага 9.

## Архитектура

- `src/js/kpi/chart_view_model.js`: чистая проекция месячных рядов и скользящих точек, диапазоны и пропуски.
- `src/js/app/reliability_report_service.js`: метод `buildKpiChartData(kpiId,state,mineId)` вычисляет один KPI через существующие Preparation и Calculator; получает месяцы выбранного рудника и таблицу выбранного месяца по всем рудникам.
- `src/js/app/reliability_kpi_chart.js`: HTML/SVG, один dialog, контролы и таблица, не рассчитывает KPI из исходных данных.
- `src/js/app/reliability_dashboard.js`: 17 кнопок «График» и одна оболочка диалога.
- `src/ui/style/05_reliability_dashboard.css`: адаптивные стили и контраст фактического/скользящего ряда.
- Изменение диапазона/окна не вызывает Calculator повторно; смена рудника запрашивает нужный ряд. Подготовка компонентов остаётся кэшированной по версии Dataset.

## Тесты и границы

Тесты `test_kpi_chart_view_model.js`, `test_kpi_chart_dialog_step7.js`, `test_reliability_report_service.js` и `smoke_app_runtime.js` проверяют реальные и отсутствующие данные, невзвешенное и взвешенное усреднение, месячные разрывы, окно, смену рудника, таблицу и закрытие. Полный GitHub Actions включает офлайн HTML, SQLite WASM и Chromium.

**Без изменений:** Dataset, SQLite, исходные формулы KPI, Report Snapshot, PDF и страница паспортов. Паспортная методика остаётся draft. Фактическая трассировка расчёта — шаг 8.
