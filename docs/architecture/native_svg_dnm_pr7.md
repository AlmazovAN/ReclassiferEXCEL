# PR 7 — Д / Н / М и операционная динамика в существующих SVG-графиках

## Цель и ограничения
Развить **нынешний собственный SVG-движок Reclassifier**, без ECharts/Highcharts/TradingView и без изменения формул, расчётов ВБР/КТГ/SLA, Calculator, Snapshot, паспортов и PDF.

В окне любого показателя есть три независимых режима визуализации:
1. **Показатель KPI** — исходный расчётный помесячный ряд. Кнопки Д и Н заблокированы, активна М. Скользящий тренд коэффициента рассчитывается существующим `KpiChartViewModel` из компонентов согласно методике, не простым средним процентов.
2. **Количество INC** — число завершённых обращений INC из ITSM по `completedAt`, без RITM. Это операционная статистика обращений, а **не** количество подтверждённых отказов для ВБР.
3. **Трудозатраты** — сумма проверенных трудозатрат задач Мобильных бригад по `factDate` из `mobileLaborFact`. Учитываются только `valid` / `valid_zero` с неотрицательной величиной. Это самостоятельный временной ряд часов, а не новая формула KPI.

## Д / Н / М и периоды
- **Д — день:** дата `ГГГГ-ММ-ДД`.
- **Н — неделя:** календарная неделя с понедельника (UTC). На графике отображается дата понедельника.
- **М — месяц:** `ГГГГ-ММ`.
- Независимые категории *1М / 3М / 1Г / Все* задают глубину обзора. График не создаёт ложных ежедневных ВБР/КТГ.
- Суммы количества обращений и трудозатрат между детализациями соответствуют одному и тому же набору исходных событий. На неделях, пересекающих край выбранного временного интервала, нельзя автоматически приравнивать суммарные значения к полному календарному месяцу.
- Для числовых объёмов скользящий тренд = арифметическое среднее количества/часов за 2–12 последних точек. Это сглаживание визуализации, **не прогноз и не изменение KPI**.
- Сохраняется тот же SVG: белый фон, линии, точки, цветовые ряды, подписи, контроль диапазона и существующие фильтры; заливки нет.
- Для защиты от перегрузки SVG отображение ограничено 366 дневными, 156 недельными или 120 месячными точками; если история длиннее, интерфейс обозначает ограничение.

## Архитектура и источники
- `kpi/operational_series.js` — чистое read-only преобразование **тех же Source Facts**, уже применяемых исходной подготовкой KPI. После первого обращения держит только компактные агрегированные строки `(день, рудник, класс оборудования, сумма)`, без ссылок на исходные ITSM/МБ записи.
- При изменении идентичности авторитетного Dataset агрегаты строятся заново. Report Service вызывает `invalidate()` при явном сбросе.
- `ReliabilityReportService.buildOperationalChartData` применяет существующие списки рудников, агрегацию ЗФ и допустимые классы; метод не изменяет `buildKpiChartMultiData`, `buildSnapshot` или Calculator.
- Для внешних Worker-запросов новых KPI не создано. Операционные ряды строятся по явному нажатию, отдельно от фоновых KPI расчётов.
- Смысловая граница: исходная дата выполнения отсутствует или не распознана — запись не может быть включена в Д/Н/М; это не приравнивается к нулю рабочего времени.
