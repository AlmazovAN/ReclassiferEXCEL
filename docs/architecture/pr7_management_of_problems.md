# PR7 — развитие раздела «Управление проблемами»

## Источники и границы достоверности
Исходные данные: обращения ITSM Сириус и зарегистрированные задачи ИС «Мобильные бригады». Связь — номер обращения МБ → нормализованный номер ITSM → поле ИТ-проблемы `PRB…`. Подготовка `ReclassifierKpiPreparePrb` использует существующий `ReclassifierKpiSourceFacts.linkMobileBrigadeToProblems`.

Одна строка МБ — одна задача. При конфликте кодов PRB для одного номера ITSM связь помечается `ambiguous` и **не считается достоверно связанной**. Отсутствие обращения (`request-not-found`) и пустой PRB (`not-linked`) тоже не считаются связанными. Дата — `mobileBrigade.factDate`; строки без пригодной даты не входят в месячный расчёт. Регламент расчёта не утверждён: показатели и их паспорта имеют `draft`, плановые цели не добавляются.

## Три новых показателя
| Показатель | Единица | Принцип |
|---|---|---|
| Задачи, связанные с ИТ-проблемами | задач | Сумма `linkedTaskCount` |
| Доля связанных задач | % | `ΣlinkedTaskCount / ΣtaskCount × 100`; при `taskCount=0` результат недоступен |
| ИТ-проблемы с зарегистрированными работами | проблем | Число **разных** `problemId` только среди однозначно связанных задач |

Показатель количества проблем **не** равен общему реестру ИТ-проблем и не означает устранение причин отказов. Если один код PRB встречается в нескольких задачах/месяцах, он считается один раз для выбранного общего периода. Для количества уникальных проблем суммирование процентов или месячных DISTINCT недопустимо; скользящее суммирование отключено. Доля задач учитывает даже строки без пригодных человеко-часов, в отличие от ранее существующей **доли трудозатрат**.

Два прежних показателя: абсолютная трудоёмкость работ с PRB и доля этой трудоёмкости — сохраняют ранее действующие формулы. В интерфейсе они названы на русском языке.

## Восемь диаграмм на экране и в PDF
1. Количество задач по состоянию связи с ИТ-проблемой (4 состояния).
2. Человеко-часы по состоянию связи.
3. Динамика числа связанных задач по месяцам.
4. Динамика доли связанных задач по месяцам.
5. Динамика доли связанных трудозатрат по месяцам.
6. Человеко-часы связанных задач по видам работ.
7. Человеко-часы связанных задач по рудникам.
8. Человеко-часы по коду ИТ-проблемы (8 ведущих кодов, остальные агрегируются).

Числа и данные диаграмм создаются из **того же** подготовленного набора и существующих результатов KPI, включаются в единый Report Snapshot, после чего неизменяемый Snapshot отрисовывается в WEB и экспортируется в PDF. `null` в месяце остаётся пропуском, а не нулём. Выбранные период, рудник и класс оборудования применяются к наборам. В месячных диаграммах показывается известная история для выбранных рудника/оборудования, как и в остальных графиках отчёта.

При отсутствии источников отображается отсутствие данных; недоступность ITSM не выдаётся за доказательство отсутствия связи с ИТ-проблемой. PDF Renderer v1.3.0 включает диаграммы и их агрегированные данные в проверяемый fingerprint PDF.

## Контроль актуальности и совместимости
После добавления трёх новых KPI старая таблица результатов KPI в SQLite может содержать снимки без этих показателей и графиков. Версия методики постоянного кэша PR5 повышена до `report-method-2026-10-pr7`, поэтому такой снимок не используется. Схема SQLite v5 остаётся прежней. Базовые 13 формул контролируются отдельным тестом без переписывания эталонов.

## Приёмка
`tests/test_problem_management_pr7.js`: новый расчёт по подготовленным строкам, нулевые и неоднозначные связи, уникальность PRB за несколько месяцев, фильтры, восемь диаграмм WEB, проверка их данных и включение в PDF. Плюс полная неизменённая регрессия CORE/FULL/SQLite/офлайн Chromium.

## Не включено
Расчёт фактически подтверждённого эффекта (сокращение трудозатрат или отказов), автоматическое открытие/закрытие ИТ-проблем, изменение корпоративного ITSM, новые данные из внешнего реестра PRB. Для таких результатов нужны другие подтверждённые источники и методики.
