# Dashboard KPI cards — шаг 4 из 9

**Статус:** новая карточка подключена к `snapshot.kpiView.cards[kpiId]` и используется всеми 17 видимыми KPI отчёта. Следующий шаг 5 — нативный modal паспорта — в этом PR не реализуется.

## Целевой вид

    ВБР навесного                   [Без оценки]
    80,4 %

    Предыдущее     Изменение       Прогноз
    79,5 %         +0,9 п.п.       —
                                   Методика не задана

Пример выше демонстрационный, не фиксированное число приложения. При утверждённом вычисленном прогнозе появятся значение, горизонт и отклонение от текущего (`+1,7 п.п.` либо отрицательная разница).

## Источник значений

| Элемент | Где лежит | Что показываем |
|---|---|---|
| Текущее | `snapshot.kpiView.cards[id].current.value` | Крупное значение с единицей измерения |
| Предыдущее | `snapshot.kpiView.cards[id].previous.value` | Только доступный предыдущий **календарный** месяц при том же фильтре |
| Изменение | `snapshot.kpiView.cards[id].change` + `changeUnit` | Дельта со знаком; процентные KPI — **п.п.**, абсолютные — их единица |
| Прогноз | `snapshot.kpiView.cards[id].forecast` | Число только при `dataState=available` и заданных `methodId` + `horizon` |
| Оценка/состояние | `status` / `current.dataState` | Без вымышленных нормативов и искусственной раскраски |
| Паспорт | Старый `renderReliabilityMethodology` | Остаётся в `<details>` до шага 5 |

Отсутствующие значения отображаются как «—». Для незаданной методики прогнозирования появляется сообщение «Методика не задана», для неподключённого KPI — «KPI не подключён», для недостаточной истории — «Недостаточно истории». При методе без горизонта или горизонте без метода число не показывается: предотвращается ложное впечатление полноценного прогноза.

Знак изменения показывает только арифметическую разницу. Положительный знак **не означает** улучшение для показателя, у которого «меньше — лучше». Цвета оценки не меняются, поскольку в каталоге ещё не утверждены нормативы.

## Границы и совместимость

- Формулы, агрегаты, `Report Snapshot`, `Calculator`, `KPI Catalog`, SQLite, PDF не изменяются.
- WEB-функция `reliabilityCardFromTemplate` читает текущие данные, предыдущее, изменение и прогноз из существующей проекции. Для старых Snapshot без `kpiView` показывает текущее значение из прежнего результата; историю или прогноз не придумывает.
- Одна функция отрисовки `renderReliabilityKpiCard` и одна группа CSS управляют оформлением всех KPI: техническая надёжность, качество данных, готовность, трудозатраты, Problem Management.
- Состояния `no-data`, `unavailable`, `insufficient`, `not-applicable` и `error` сохраняют исходные предупреждения; при недоступном текущем не показывается число из устаревшего результата.
- Заголовок, оригинальные диаграммы, фильтры и существующий паспорт в раскрывающемся блоке сохраняются до собственных следующих шагов.
