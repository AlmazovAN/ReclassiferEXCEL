# KPI Passport modal — шаг 5 из 9

**Статус:** реализован один нативный `<dialog>` для всех 17 карточек отчёта по надёжности с общим renderer содержания из действующего KPI Catalog. UI страниц «Паспорта KPI» будет следующим, шестым этапом.

## Что теперь происходит

1. На каждой карточке вместо раскрывающейся методики расположен отдельный `<button type="button">Паспорт KPI</button>`. Для неподключённых KPI кнопка также доступна и показывает честную карточку отсутствующей методики.
2. Открытие кнопкой использует один экземпляр `<dialog id="reliabilityKpiPassportDialog">` с `showModal()` — настоящая модальность, а не `window.open` / произвольный overlay.
3. Функция `bindReliabilityPassportDialog(dashboard)` передаёт `kpiId` и **тот же текущий Report Snapshot** в `ReclassifierKpiPassportView.renderContent(kpiId, {snapshot})`.
4. Нативный dialog удерживает клавиатурный фокус и закрывается клавишей Escape; также есть крестик «Закрыть паспорт KPI» и закрытие по клику на backdrop. При закрытии фокус возвращается на исходную кнопку.
5. Модальное окно создаётся **один раз** внутри страницы дашборда, не в каждой карточке. Содержимое обновляется при выборе KPI. При следующем рендере фильтров создаётся актуальный DOM с новым Snapshot, старый вывод не сохраняется.
6. Используется локальный модуль, собранный в автономный HTML; внешних шрифтов, запросов, pop-up и сторонних библиотек нет.

## Содержание паспорта

| Раздел | Источник |
|---|---|
| Идентификатор, название, назначение, единица, оценка, версия и статус | `ReclassifierKpiCatalog.get(kpiId).definition` |
| Формула и версии исполняемых обработчиков | `.calculation.formula`, `.preparationHandler`, `.formulaHandler` |
| Dataset, используемые семантические поля, исходный заголовок (если известен), правила `null` | `.calculation.sources[].fields[]` |
| JOIN: ключи, тип связи, кардинальность, отсутствие соответствий, дубликаты | `.calculation.joins` |
| Фильтры: операторы, значения, этап и область применения к числителю/знаменателю | `.calculation.filters` |
| Последовательность операций FILTER, COUNT, SUM, DIVIDE, SUBTRACT и др. | `.calculation.steps` |
| Зерно, способ объединения компонентов, нулевой знаменатель и округление | `.calculation.aggregation` + `.formula` |
| Даты, предыдущий период, история, rolling, прогноз и ограничения | `.calculation.temporal` |
| Состояние, компоненты фактического результата, время, ревизии, хеши | Текущий `Report Snapshot` (`results`, `query`, `sources`, `kpiView`) |

**Важно:** контракт описывает алгоритм и его шаги, но **не является** полной фактической трассировкой исполнения. Компоненты `KPI Result` можно показать сейчас; действительные числа отфильтрованных строк и реальные промежуточные операции будут инструментированы на **шаге 8**. Поэтому здесь явно написано, что расчётная цепочка — декларация, а не исполненный журнал.

**Важно:** расчётные формулы не копируются и не переопределяются в интерфейсе. Математика остаётся в Calculator. Паспортные поля перечислены по существующему `Calculation Contract` со статусом `draft`; неизвестное название физической колонки **не выдумывается**. Неутверждённые значения цели, прогноза и неподключённых KPI обозначаются как не определённые.

## Архитектурная граница и переиспользование

- `src/js/kpi/passport_view.js` — чистый renderer по `kpiId`, без DOM-побочных эффектов, доступа к SQLite или расчётов. Публичный API: `globalThis.ReclassifierKpiPassportView.renderContent(kpiId,{snapshot})`. Следующий шаг 6 может использовать эту же функцию для отдельной страницы без копирования шаблона.
- `src/js/app/reliability_dashboard.js` — единственный владелец DOM-процесса открытия/закрытия паспорта на дашборде; больше не содержит устаревший `renderReliabilityMethodology`.
- `src/ui/style/05_reliability_dashboard.css` — модальная оболочка, таблицы и мобильное представление (горизонтальная прокрутка широких расчётных таблиц).
- `build/build.py`, `tests/test_js_fragment_contract.py`, `tests/smoke_app_runtime.js` — точный порядок загрузки JS-фрагментов в монолитной offline-сборке.
- Без изменений: `KPI Result`, `Report Snapshot`, Dataset, SQLite, математические формулы, PDF и диаграммы.
