# PR-8 — Раздельное отображение прогнозов по типу показателя

## Цель

Оформить уже рассчитанный в PR-1–PR-7 экспериментальный прогноз **последнего
незавершённого отчётного месяца**. Не менять исходные фактические KPI,
формулы, Dataset, источники и методы прогнозирования.

## Процентные KPI

Для ВБР/КТГ с `forecastType='reporting-month-nowcast'`:

- Завершённые месяцы остаются сплошной линией и обычными точками.
- **Промежуточный факт последнего месяца остаётся в KPI Result и подсказке,
  но не изображается как отдельная точка или обычная числовая подпись.**
- От предыдущего завершённого месяца к прогнозу итога того же месяца
  строится пунктирный сегмент; значение прогноза подписано бледнее.
- Ось Y и последнее значение скользящего тренда не масштабируются по
  невидимому промежуточному проценту.
- Если в выбранном масштабе только одна точка, отображается прогнозная
  точка без выдуманного начального сегмента.

## Абсолютные метрики

Для завершённых INC, трудоёмкости МБ и KPI часов по
`forecastType='reporting-month-volume-nowcast'`:

- Исторические значения и факт последнего месяца соединены обычной
  сплошной линией.
- Накопленный факт последнего месяца остаётся **обычной точкой и обычной
  подписью даже при выключенных остальных подписях**.
- На том же X (тот же отчётный месяц) добавляется бледная прогнозная
  точка и бледная числовая подпись; между накопленным фактом и прогнозом
  рисуется **вертикальный пунктирный сегмент**.
- Пример: факт 847 чел.-ч → прогноз 1 350 чел.-ч, без замены значения
  847 в Calculator/Report Snapshot.
- Прогноз не используется для дневной и недельной шкалы: PR-7 выдаёт
  только прогноз полного месяца. Их фактические точки не меняются.

## Вход и guards

Единый UI-adapter `kpiChartForecastState(series,view,unit,scale)`
только проверяет результат из Report Service:

- `dataState='available'`;
- конечное значение прогноза и последнего факта;
- тип прогноза соответствует единице измерения (`%` или абсолютная);
- `horizon` равен последнему отображаемому месяцу;
- `observedValue` **точно** равен фактическому значению последней точки;
- шкала `month`.

Нельзя менять `dataState`, подставлять факт вместо отсутствующего
прогноза или вычислять новый метод в UI. При ошибке проверки
отображается обычный фактический ряд без дополнительного пунктира.
Для одной серии и нескольких серий логика одинакова.

## Где применяется

- `reliability_kpi_chart.js`: SVG-представления KPI и операционных
  метрик INC/чел.-ч; пояснения и всплывающие подсказки.
- `reliability_dashboard.js`: основной SVG ВБР и вторичное значение
  прогноза трудоёмкости в карточке с пояснением факта.
- PR-9 согласует PDF/паспорт и сертифицированный интервал реального
  импорта Dataset; сам PR-8 методику источников не меняет.

## Приёмка

`tests/test_forecast_visual_pr8.js` проверяет:
скрытую промежуточную точку процента при доступном прогнозе,
сохранённую фактическую точку и подпись часов/INC,
одинаковый месячный X, два независимых значения, подсказку cutoff,
недоступный прогноз, несовпадение горизонта/факта и запрет пунктира
для дневной/недельной шкалы.

Весь проект проходит прежние регрессионные тесты PR-1–PR-7 и полную
offline Chromium-приёмку единого HTML перед слиянием PR.
