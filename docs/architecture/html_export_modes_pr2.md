# PR 2 — Возврат «Скачать HTML» и разделение режимов экспорта

## Причина исчезновения

После перевода Runtime на SQLite-first HTML-снимок применённых Dataset стал доступен только при **закрытой** Reclassifier.db. Раздел `src/js/app/database_ui.js` полностью скрывал кнопку `downloadUpdatedHtmlButton` при `mode() === 'sqlite'`. Ограничение было намеренным: копировать в HTML устаревший Legacy Dataset Store, когда авторитетным источником стала SQLite, запрещено.

## Два разных продукта экспорта

| Действие | Когда доступно | Что содержит | Чего не содержит |
| --- | --- | --- | --- |
| **Скачать HTML** | В режиме SQLite и без SQLite (после загрузки baseline; недоступно во время занятой операции БД) | Автономную копию **текущей сборки приложения** и **исходные baseline-данные**, которые уже вшиты в эту сборку | **Текущие** изменения открытой SQLite, неподтверждённые кандидаты Excel и накопленный HTML Dataset Pack |
| **Скачать HTML с данными** | Только без открытой SQLite | Эту же сборку и подтверждённые Dataset, записанные в `reclassifierDataPack` (формат 2; с Full Dataset при наличии) | Неподтверждённые кандидаты и рабочие изменения открытой SQLite |
| **Скачать Reclassifier.db** | При открытой SQLite | Целостную активную рабочую БД после её проверки | HTML-код приложения |

Нельзя путать «Скачать HTML» с резервным копированием текущей БД: если рабочие данные были изменены после выпуска стартовой HTML-сборки, для их сохранения **обязательно отдельно скачать Reclassifier.db**. В HTML-приложении могут находиться встроенные исходные данные сборки, поэтому его не следует считать пустым или обезличенным.

## Поведение

- «Скачать HTML» находится в верхней панели раздела «Работа с базой данных» и **не скрывается** при подключении Reclassifier.db.
- Экспорт работает без интернета, копирует документ и убирает текущий контент страницы, выбранный маршрут и старый `reclassifierDataPack`; исходная открытая страница при этом не изменяется.
- Файлы именуются `Reclassifier_v<версия>_Application_<дата>.html` и `Reclassifier_v<версия>_Data_<дата>.html`.
- HTML-снимок в SQLite-режиме по-прежнему **запрещён** и проверяется повторно после асинхронного сжатия. Данный PR не создаёт второй авторитетный набор данных и не меняет Dataset Store.
- Блокировка операций во время `databaseWorkspaceState.busy` предотвращает нажатия в переходных состояниях. Никакого автоматического сохранения БД при скачивании HTML не выполняется.

## Проверки

1. Unit: переносимый HTML-снимок в режиме Legacy содержит только подтверждённые Dataset; повторное открытие восстанавливает данные.
2. Unit: копия приложения очищает существующий dataset pack, не включает незафиксированные предпросмотры и не меняет открытую страницу.
3. Unit: при открытой SQLite HTML-снимок блокируется, а автономную копию приложения можно выгрузить без чтения данных из SQLite.
4. Offline Chromium: при открытой SQLite одновременно присутствуют кнопки HTML-приложения и SQLite, HTML-снимок скрыт; скачанный `_Application_` содержит встроенный baseline и пустой `reclassifierDataPack`.
5. Регрессии сборки, данных, отчёта, PDF и формул KPI остаются обязательными.

Этот PR **не** реализует экспорт изменённой SQLite непосредственно в переносимый HTML с текущими данными. Это отдельная будущая задача со схемой согласования состояния и проверки целостности, если появится такое требование.
