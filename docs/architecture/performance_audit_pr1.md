# PR 1 — Инструментальный аудит производительности

## Назначение

Добавить измерения времени и количества операций, не меняя формулы KPI, Dataset, SQLite, Report Snapshot, отрисовку графиков и расчёт прогнозов. Это диагностический этап **до** оптимизации.

## Что измеряем

- `startup.hydrate.total`: восстановление стартовых Dataset (включая подготовку источников).
- `report.snapshot.total`: холодный и повторный вызовы Report Service; `report.snapshot.cache.hit/miss`.
- `report.prepare`, `report.monthly.series`, `calculator.batch`, `calculator.kpi`: стоимость подготовки и повторных вычислений.
- `report.chart.multi`, `report.chart.summary`: наборы точек и сводная формула.
- `dashboard.render.total`, `dashboard.render.dom`: отображение страницы и обновление DOM.
- `chart.ui.fetch`, `chart.ui.paint`: запрос и отрисовка сравнительного графика.
- `passport.snapshot.fill`, `pdf.render.total`: паспорта и PDF.
- `main.longtask`: Long Tasks, если браузер поддерживает PerformanceObserver.
- `usedJsHeapBytes`: приблизительная JS-память, если браузер предоставляет performance.memory.

В разделе **Журнал** доступна сводка измерений, счётчики и кнопка «Скачать профиль JSON». Профиль содержит только имена фиксированных этапов, длительности и числа вызовов. Файлы, записи ITSM/МБ, названия рудников, выбранные фильтры и персональные сведения не записываются.

## Методика замера

1. Открыть одну и ту же FULL HTML-сборку и тот же набор Dataset в Chromium.
2. В журнале сбросить замеры, сделать первый переход в «Отчёт» и сохранить профиль.
3. Повторно открыть отчёт без изменения Dataset и сохранить профиль.
4. Изменить месяц, рудник и класс оборудования по очереди.
5. Открыть один и тот же KPI-график два раза и один раз выбрать «Все».
6. Открыть паспорт KPI и скачать PDF, затем сохранить профиль.
7. Повторить сценарий после обновления одного Dataset для проверки инвалидации кэша.
8. Сопоставить с результатами последующих PR на той же машине и с теми же исходными данными.

Для достоверного сравнения холодного старта необходимо **полностью перезапускать страницу**, а не только нажимать «Сбросить замеры»: сброс не очищает готовые данные приложения.

## Границы интерпретации

- Время синхронных операций измеряется как wall-clock длительность их вызовов. Вложенные интервалы входят в родительские и **не суммируются** при определении общего времени.
- Время DOM update измеряет JavaScript и изменение DOM, но не гарантированное завершение CSS layout/paint. Long Tasks лишь косвенно показывают блокировку главного потока.
- `recentP95Ms` — 95-й процентиль **последних ограниченных 250 событий**, а не статистика всего сеанса.
- `usedJsHeapBytes` доступен не во всех браузерах и не равен полной памяти процесса.
- Профиль выключается через API `ReclassifierPerformanceProfiler.setEnabled(false)`; экспорт без сети.
- Абсолютные пороги задержек в CI не используются: среда GitHub Actions нестабильна по времени исполнения.

## Приёмка

- Тест `tests/test_perf_instrumentation.js` + обычный CI и автономный Chromium.
- Сохранены все контрольные KPI Result, расчётные компоненты и идентичность кэшированных Snapshot.
- Холодные/тёплые вызовы, hit/miss, обработка месяцев и построение графика представлены раздельно.
- Отчёт профиля не содержит исходных записей Dataset и данных фильтров.
