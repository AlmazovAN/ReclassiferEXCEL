# V4-11 — независимая проверка полной цепочки

V4-11 не классифицирует заново и не переносит ответы из исходной, инженерной или legacy-разметки. Он получает четыре уже сформированных решения V4-07–10, исходное заключение по событию V4-06 и индекс V4-04. Проверяет полное совпадение выбранных четырёх значений с **точной действующей веткой** и согласованность родителей, происхождения словаря, статусов, следов фактов и согласованной семантики причины.

Статусы: `COMPLETE_UNVERIFIED` (формальная цепочка есть, но независимой фактической проверки нет), `EXPLICIT_UNKNOWN_CAUSE` (словарная причина *не установлена*, поэтому механизм отказа не определён), `INCOMPLETE`, `INCONSISTENT`, `NOT_APPLICABLE`. Результаты `classificationComplete`/`causalMechanismKnown` выставляются только при `COMPLETE_UNVERIFIED`. Во **всех** случаях `readyForApply=false` и `independentlyVerified=false`.

Проверка полей и символьных смещений диагностики позволяет выявлять повреждённый аудиторский след. Наличие версии/отпечатка справочника желательно: при отсутствии отображается предупреждение, версия не выдумывается. Входные объекты не изменяются.

В отчёт добавлены колонки CC:CF: путь, статус, доказательства и ограничения. Всего 84 колонки A:CF. Ни исходные/инженерные результаты, ни legacy 3.3, ни SQLite не меняются. Этот этап — **аудит согласованности**, а не инженерное подтверждение физической причины. Для дальнейшей готовности нужны проверка реальных обращений и отдельная политика применения.
