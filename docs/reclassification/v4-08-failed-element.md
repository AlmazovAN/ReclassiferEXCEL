# V4-08 — второй уровень независимой классификации

## Граница этапа

Элемент выбирается только после V4-07, при установленном отказе, единственном выбранном оборудовании и диагностированном отказавшем объекте уровня `element`. Совпадение имени объекта с действующей веткой индекса V4-04 обязательно. Никакая первичная, инженерная или legacy-классификация не участвует.

`SELECTED` означает выбранное по авторскому диагностическому утверждению каноническое имя элемента, **не подтверждённый физическим осмотром факт**. Выбор элемента не доказывает неисправность и причину; третья и четвёртая позиции остаются `null`. `readyForApply=false`.

Если V4-07 неоднозначен, противоречив или содержит несколько объектов — `BLOCKED_BY_OBJECT`. Когда V4-07 установил только оборудование, не выбираем произвольного потомка — `UNRESOLVED`. Для неотказа — `NOT_APPLICABLE`. Несоответствие словарю — `NOT_IN_CLASSIFIER`. В каждом случае сохраняются ограничения; отсутствие доказательств не превращается в отрицание дефекта.

## API

`ReclassifierElementAssessmentV4.analyze(objectAssessment,objectContext)` возвращает глубоко неизменяемое решение со статусом, диагностическим основанием с позициями, допустимыми кандидатами, `candidatePath`, происхождением индекса и запретом применения. Используется существующий подготовленный индекс; дополнительного справочника и автоматических алиасов нет.

## Гарантии

- Остаётся без изменений Re-Class 3.3 и экспорт O:T / отдельный Reclassification.
- V4 не применяется к SQLite/ITSM.
- Не используются исходные/инженерные классификационные ответы, MB-комментарии и выводы 3.3.
- Регрессии: доказательная связь, неоднозначность, неизвестный элемент, отсутствие прямого элементного доказательства, неизменяемость и независимость.
