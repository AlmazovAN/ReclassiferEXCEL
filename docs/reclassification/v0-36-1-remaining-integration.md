# Reclassifier 0.36.1 — незавершённая интеграция V4 и контроль WebWorker

Дата: 20.10.2026. Основание: ошибка «WebWorker не завершил операцию за 10 минут» при обработке всей ITSM-базы; согласованный эталон ITSM A:AL.

## Контракт Excel

- Лист ITSM: две строки заголовков, данные с третьей, ровно **92 колонки A:CN**.
- **A:AL (38)**: точные имена и порядок из согласованной ITSM-выгрузки; исходные V = «Примечания к разрешению», W = «Доп.информация по причине» остаются **раздельными**.
- **AM:CN (54)**: точный существующий массив `ReclassifierTechnicalDiagnosticsV4.columns`, без дублирования legacy diagnostic columns.
- Исходные E:H и инженерные J:M не изменяются.
- O:T и отдельный 10-колоночный Reclassification пока отражают **legacy 3.3**, не независимые изменения V4.
- V4-12 запрещает автоматическое применение; полный путь является кандидатом для инженерного утверждения.

## Ошибка тайм-аута

Проверенный дефект: `worker_client.js` использовал фиксированные 10 минут для всего запроса, даже при `WORKER_PROGRESS`. После тайм-аута Worker мог оставаться активным.

В рабочей ветке:

1. Для `PROCESS_RECLASSIFICATION` используется сбрасываемый при прогрессе watchdog (20 минут неактивности), с указанием последней стадии.
2. Реально зависший Worker останавливается; повторный запрос создаёт новый.
3. Формирование сравнительного листа даёт пакетный прогресс и уступает event loop; этапы XLSX-сжатия отображаются.
4. V/W выводятся отдельно; штатное объединённое примечание сохранено лишь для прежнего контракта ReClass.
5. Кнопки «Скачать диагностику V4 (ITSM A:CN)» и «Скачать реклассификацию (3.3)» разделены. Устаревшие результаты очищаются перед новым запуском.


## Результат первого запуска Codespaces (20.10.2026)

Первый полный прогон: **23 PASS / 3 FAIL**; функциональные проверки V4 и сборка CORE прошли. Три отказа были вызваны тестами, сохранявшими прежние ожидания для сравнительного отчёта:

1. `test_reclassification_worker_processor.js` требовал объединённую колонку «Примечания к закрытию (объединённые с доп)» на листе ITSM вместо отдельных V/W.
2. `test_reclassification_legacy_v4_01.js` ожидал старые 34 исходных заголовка; теперь frozen legacy проверяется отдельно от нового контракта отчёта 38+54.
3. `test_reclassification_load_pr7.js` ожидал `A1:CJ5002` и `A2:CJ5002` вместо `A1:CN5002` и `A2:CN5002`.

Тесты обновлены. **Не считать их успешно пройденными, пока не получен повторный прогон Codespaces**. При несовпадении значений, а не только заголовков, исправлять саму реализацию, а не ослаблять проверки.

Дополнительная проверка: Active Runtime может уже содержать штатно объединённое V+W, несмотря на наличие отдельного W. Для V4 исходное V извлекается только через точное обратное преобразование известного суффикса `Доп.информация по причине: ...`; несовпадающие данные сохраняются без угадывания. Старый десятиколоночный экспорт по-прежнему использует объединённое поле.

## Условия завершения

- Запустить `node tests/test_worker_client.js`, `node tests/test_reclassification_worker_processor.js` и полную регрессию тестов ITSM/V4.
- Проверить XLSX на приложенном исходном Excel и на полном Active Runtime, включая раздельные V/W, контроль A:CN, дополнительные листы, даты, номера и повторное открытие.
- Проверить длительность и расход памяти, прежде всего `XLSX.write` и ZIP formatting, на базе, вызвавшей 10-минутную ошибку.
- Если в Active Runtime исходный W утрачен вследствие исторического объединения V/W, отобразить предупреждение вместо выдумывания исходного W.
- Собрать в Codespaces CORE HTML из исходников и проверить в браузере обе кнопки и поведение после ошибки.
- Только после этого объединить PR и публиковать 0.36.1. Текущий статус — **PR для тестирования, не релиз**.
