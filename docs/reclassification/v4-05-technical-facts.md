## Объём

Чистый модуль `src/js/modules/reclassification/facts_v4.js` выделяет **симптомы / диагностику / действие / результат**. Термин «симптомы» принят по указанию пользователя. Модуль не определяет факт отказа, тип INC/RITM, отказавшее оборудование, классификационную ветку или техническую причину. V4 остаётся недоступен для применения и экспорта (`V4_NOT_IMPLEMENTED`). Legacy не изменяется.

PR зависит от V4-04 (PR #291, `6940e32aee2237542e1a7c77567270811bb18596`). Пока V4-04 не принят, V4-05 направляется в его ветку; это не разрешение объединять зависимые изменения в main.

## Контракт

`ReclassifierTechnicalFactsV4.extract(row)` принимает только исходные текстовые поля `shortDescription`, `description`, `closureNote`, `extraReason`. Не читает номер обращения, инженерные и штатные классификации, ответы legacy, SQLite или Active Runtime. Возвращает глубоко замороженный объект; исходные данные неизменны. Копии модуля включаются штатной сборкой в Browser и WebWorker перед V4 engine. Для вызова извлечения используется отдельный API; регистрация готового движка не выполняется.

Каждый фрагмент содержит `id`, `field`, `start`, `end`, точный исходный `text`, `kind`, русскую метку `label`, `assertion`, лексические `mentions`, `temporalMarkers`, `sequenceInField` и `independentlyVerified: false`. Смещения в единицах UTF-16, как `String.slice(start,end)` JavaScript, конец исключительный. Пунктуация предложения сохраняется; разделители и пробелы между фрагментами могут отсутствовать. Исходное поле остаётся источником полного текста.

Роли: `symptoms`, `diagnosis`, `action`, `result`, `unknown`. Явные заголовки «Симптомы:», «Диагностика:», «Действие:»/«Действия:», «Результат:» задают роль до следующего заголовка в том же поле. Без заголовка применяются ограниченные русскоязычные лексические признаки. Нераспознанный текст сохраняется как `unknown` с предупреждением `UNRESOLVED_ROLE`, а не отбрасывается.

| Статус утверждения | Значение |
|---|---|
| `reported` | Описанные симптомы |
| `stated` | Автор текста утверждает наблюдение, действие или результат |
| `negated` | Явно отрицается наблюдение, выполнение действия или результат |
| `hypothesis` | Предположение, условие или вопрос |
| `planned` | Необходимое, рекомендованное или будущее действие |
| `ambiguous` | В одном фрагменте остались разные утверждения; нужен разбор |

Ни `stated`, ни `reported` **не означают независимо подтверждённый технический факт**. Числовая уверенность не вводится. «Нет изображения» — утверждение симптома, «обрыв не подтверждён» — отрицание подтверждения, «возможно перегрев» — гипотеза, «требуется заменить БП» — план, «заменили БП» — утверждение действия, которое само по себе не доказывает отказ блока.

Лексические упоминания камеры, кабеля, БП, коммутатора и датчика снабжены исходными фрагментами. Это ограниченный стартовый список якорей для последующих этапов, **не канонические значения классификатора, не словарь эквивалентных алиасов V4-04 и не выбор отказавшего объекта**. Неизвестное оборудование остаётся в полном тексте. Составные неразделённые действие + наблюдение получают роль `unknown` и предупреждение `MIXED_STATEMENTS`; статус предположения или плана сохраняется, иначе используется `ambiguous`.

## Последовательность и ограничения

Разделение выполняется по предложениям, переводам строк, точке с запятой, переходам «но», «а», «затем», «после этого». Позиции и порядок внутри каждого поля сохраняются. Лексические маркеры времени и часы сохраняются вместе со смещениями. Порядок обхода полей **не является хронологией события**: `chronology.crossFieldOrderKnown: false`. Время не интерпретируется как абсолютная дата; противоречия не разрешаются и причинные связи не достраиваются.

Это детерминированный каркас технического прочтения с ограниченными эвристиками, не универсальный русский NLP. Сложные отрицания, перечисления нескольких объектов, вложенная прямая речь и смешанные фразы требуют дальнейшей проверки. Пропущенные поля перечислены в `missingFields`; нетекстовые значения дают `NON_TEXT_FIELD` без преобразования произвольных объектов в текст. Для любого результата `readyForClassification: false`.

Реальные инженерные Excel и полная дорожная карта на 14 PR в текущем наборе файлов отсутствуют. Предметный объём принят из переданного контекста: извлечение, последовательность, роли, отрицания и гипотезы. Качество на производственных обращениях и полнота терминологии не подтверждены. Перед дальнейшим развитием нужны обезличенные случаи с согласованной разметкой фрагментов и отрицаний.

## Проверка

Синтетические проверки покрывают роли, заголовки, отрицания, гипотезы, планы, смешанные высказывания, границы отрицаний между фрагментами, точность исходных смещений, маркеры времени, неизменность и отсутствие доступа к контрольным классификациям. Проверка сборки отдельно сверяет точный исходник и синтаксис обеих копий Browser/Worker. Существующий full runner V4-04 повторно проверяет V4-01–04, экспорт 75/10, 5 000 строк, CORE и startup smoke.

```bash
bash tests/run_v4_05_codespaces.sh full
tail -n 100 ~/v4-05-codespaces.log
```

Запускать как дочерний процесс, не `source`. По умолчанию код выхода 0 сохраняет интерактивный терминал: итоговое число ошибок и вложенные PASS/FAIL обязательны к прочтению. Для автоматической приёмки: `V4_05_STRICT=1 bash tests/run_v4_05_codespaces.sh full`. Журнал можно задать через `V4_05_LOG_PATH`. UTC закреплён только в процессе тестирования существующего контракта дат.
