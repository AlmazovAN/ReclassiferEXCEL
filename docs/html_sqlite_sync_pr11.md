# PR 11 — HTML ↔ SQLite: выбранный Active Runtime

## Источник истины
При подключённой SQLite рабочий источник — SQLite. Кнопка «Синхронизировать HTML и SQLite» переносит согласованный снимок **только SQLite → HTML Dataset Store**; обратная перезапись SQLite запрещена. Без SQLite кнопка неактивна.

## Сохранение HTML
«Сохранить HTML с данными» в любом режиме читает активный Runtime:
- в HTML-режиме — данные HTML Dataset Store;
- в SQLite-режиме — актуальные записи и метаданные SQLite, без обязательной предварительной синхронизации.

HTML содержит сериализованные применённые Dataset, Full Dataset (в том числе частичные Raw), данные ITSM/МБ, Equipment History, справочники и версии. Equipment Combined является производным и при загрузке пересобирается из исходных пяти каталогов.

## Защита данных
- Перед копированием вычисляется fingerprint UUID базы и полных строк Dataset Registry (ревизии, хеши, счётчики). После чтения/сжатия и перед публикацией проверяется неизменность. При изменении источника операция отклоняется.
- Декомпрессия, проверка контрольной суммы, схемы и Full Dataset выполняются **до** публикации.
- Для ручной синхронизации публикация HTML mirror — единая проверенная атомарная замена внутренних Dataset. Она не меняет SQLite и не переключает Active Runtime.
- Повторное нажатие не создаёт дублей; при отсутствии в SQLite Dataset удаляется только соответствующая устаревшая копия в неактивном HTML Store.
- Сохранение HTML — снимок, не транзакция изменения бизнеса и не гарантия записи файла браузером на диск; результат загрузки файла следует проверить.
- Контейнер автономен **по данным относительно SQLite**. Полная независимость от сети требует отдельной проверки сборки и зависимостей.

## Границы
Не реализуется двустороннее слияние конфликтов, импорт HTML в текущую SQLite, совместная запись в один сетевой SQLite-файл несколькими ПК. Сетевое размещение сохранённого HTML/SQLite — внешняя операция пользователя. Общее стресс-тестирование больших баз и переносимости на корпоративные ПК — PR 12.
