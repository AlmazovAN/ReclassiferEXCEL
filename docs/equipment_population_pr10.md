# PR 10 — Equipment Population (историческая численность оборудования)

## Назначение
Предоставить **читаемый, не изменяющий данные** расчёт числа единиц Equipment на дату по сохранённым PR9 наблюдениям подтверждённых полных секций. Он не меняет Drivers, расчёт КТГ, ITSM, МБ или актуальный Equipment_Combined.

## Контракт
- API: `ReclassifierEquipment.population({asOf:'YYYY-MM-DD', mine:'Октябрьский', sources:['stationary','mounted']})`.
- По умолчанию учитываются только физические каталоги `stationary` и `mounted`. Каталоги `transport`, `transport_start_points` и `zabbix` доступны отдельно, но никогда не смешиваются с физическим количеством по умолчанию (Zabbix — мониторинговый срез, StartPoints — служебные записи).
- Для каждого `source + mine` выбирается самый поздний подтверждённый полный снимок с `sourceDate <= asOf`. Наблюдения других рудников не заменяют снимок запрошенной секции.
- `notWorkingSince`, когда дата подтверждённо распознаётся, определяет неактивность с соответствующего календарного дня. Непонятная непустая дата — `uncertain`, не `active`.
- Ни `commissioningDateUnverified`, ни `first_observed`, ни дата загрузки не являются датой ввода оборудования.
- Когда для нужного источника/рудника до выбранной даты нет достоверного снимка, `coverage:'incomplete'`, `active:null`, `total:null`. `observedActive` может быть показан как частичная сумма, не общий итог.
- Результат включает `bySource`, `groups` по `source/mine/equipmentType`, `unavailable` с причинами и метаданные последнего источника наблюдения.
- Алгоритм не реконструирует физический день перемещения и непрерывную историю работы между снимками. Это численность **по последнему наблюдению**, а не доказанный состав в любую промежуточную дату.

## Ограничения и продолжение
Пока UI-кнопка исторической численности не добавляется: безопасный read-only API доступен через существующий Equipment facade. Дальнейшие UI-отчёты могут использовать агрегаты без изменения модели хранения. Полная интеграционная проверка миграций HTML/SQLite и крупных массивов данных относится к PR 12. Старые наборы без PR9-истории должны возвращать неопределённость вместо фиктивного нуля.
