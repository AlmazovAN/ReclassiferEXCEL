# PR-8 — протокол приёмки накопительной SQLite

**Объект:** автономный Reclassifier CORE HTML и отдельно подключаемый Reclassifier.db.
**Источник автоматических данных:** синтетическая SQLite и встроенный SQLite WASM, без корпоративных выгрузок или сетевых запросов.
**Статус:** выполнение тестов фиксируется в GitHub Actions; текущий файл — перечень критериев, не доказательство фактической приёмки на рабочем ПК.

## 1. Матрица автоматических испытаний

## 2. Ручная приёмка в корпоративной Opera

**Использовать только отдельную копию базы.** Сохранить ещё одну резервную копию вне рабочей директории. Зафиксировать версию Opera, объём базы, память и свободное пространство.

1. Скачать CORE из проверенного GitHub Release, открыть автономно без сети. Подключить *копию* существующей SQLite.
2. Сопоставить количество Dataset, строк, import_history и результаты проверки целостности с контрольными значениями.
3. Импортировать небольшую выгрузку ITSM/МБ, сверить предпросмотр и результат COMMIT. Повторить файл — проверить отсутствие дубликатов.
4. Выполнить «Пересчитать всё (предпросмотр)», сверить ITSM/МБ и связанный KPI Source, затем подтвердить запись.
5. Проверить, что COMMIT в браузере не равен физической записи в исходный файл. Сохранить подключённую копию базы с обратной побайтовой проверкой.
6. Закрыть HTML, снова открыть записанную копию и проверить изменения, метрики, Registry и историю.
7. В отдельной тестовой копии изменить OS-файл извне: система должна заблокировать запись по старым размеру/времени.
8. Проверить автосохранение: ручное включение, права, запись после изменения, реакция на ошибку. В новой вкладке автосохранение должно быть отключено.
9. Проверить доступность IndexedDB, свободную квоту и создание/восстановление контрольной точки только на тестовой копии. Восстановление не должно само менять исходный OS-файл.
10. На объёме реальной SQLite около 461 МБ выполнить загрузку, инкрементальный импорт, пересчёт, сохранение, повторное открытие и записать фактическую длительность и память.

## 3. Границы подтверждения

- Автоматический CI не подтверждает поддержку File System Access и IndexedDB корпоративной Opera и не использует пользовательскую 461-МБ базу.
- Chromium может принять автономный CORE, но это не равнозначно испытанию в корпоративной Opera.
- IndexedDB — дополнительная, потенциально удаляемая браузером копия, а не гарантированная резервная копия.
- Полный поддерживаемый пересчёт касается МБ и ITSM; KPI Source меняется вследствие ITSM, Equipment Catalog и остальные справочники не пересчитываются автоматически.
- PR-8 считается автоматически принятым только после успешного PR CI, merge, отдельного успешного main CI и проверенного HTML в GitHub Release. Реальную эксплуатационную приёмку требуется провести отдельно.
