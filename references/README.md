# References

В этот каталог нельзя добавлять реальные корпоративные справочники.

Здесь хранятся только документация, схемы колонок и при необходимости синтетические примеры без рабочих данных.

Текущие логические справочники:

- `reclassification` — выработанный справочник ReClass;
- `drivers` — схема 1.0.0 реализована в Reference Manager;
- `customers`;
- `type_request`;
- `initiators`;
- `exceptions`;
- `problem_grade`.

## Drivers 1.0.0

Фактический вход — широкая Excel-таблица:

```text
Наименование типа узла/бъекта/оборудования | Сервис | Система | <рудник 1> | <рудник 2> | ...
```

Целевой контракт для аналитических модулей:

```text
mine | name | service | system | value | unit
```

Колонки рудников определяются динамически по непустым заголовкам справа от `Система`; реальные названия рудников не зашиваются в код.

`Сервис` и отдельные значения связи могут быть пустыми. Пустое значение считается «не задано» и не является конфликтом с заполненным значением в другой строке. Предупреждение создаётся только для разных непустых значений `Сервис` или `Система` у одного наименования.

Drivers не содержит даты заявки, поэтому показатель свежести для него не применяется. Реальные Excel-файлы в репозиторий не помещаются.


## Reclassification / ReClass 1.0.0

Формат определяется по заголовкам `Дата регистрации`, `Дата выполнения обращения`, `Номер`.
Пустые значения допустимы. `Номер` сохраняется как ключевое поле обращения.
Обе даты нормализуются в `YYYY-MM-DD`.
Свежесть = максимум по `Дата выполнения обращения`; сортировка нормализованного набора выполняется по этой же дате по возрастанию.


## Initiators 1.0.0

Формат определяется по четырём заголовкам: `Инициатор (открыл)`, `Группа инициаторов`, `Группа инициаторов с коментами`, `комменты`.
Пустые ячейки и значения из вопросительных знаков считаются неизвестными и нормализуются в `null`.
Повторные строки одного инициатора объединяются с приоритетом заполненных значений. Свежесть не применяется.


## ProblemGrade 1.0.0

Ключ привязки строится самим Reference Manager из полей `Наименование оборудования`, `Элемент`, `Неисправность`, `Причина`.
`Вспомогательный столбец` используется только для проверки исторической Excel-склейки и не участвует в поиске.
Точные дубли объединяются; несколько IT-проблем на одной классификационной цепочке сохраняются как несколько привязок и отмечаются предупреждением.
Свежесть не применяется.


## Customers 1.1.0

Формат определяется по заголовкам `Рудник`, `Заказчик (для нас)`, `Заказчик кратко`, `Заказчик полностью`. Для совместимости также принимается старый заголовок `Заказчик`.
Начальный префикс `р.` / `ш.` удаляется только из нормализованного ключа `mine`; исходное название сохраняется как `mineSource`.
`Заказчик (для нас)` — внутренняя принадлежность (например, ЗФ/КФ); краткое и полное наименование относятся к фактическому заказчику. Один внутренний заказчик может соответствовать нескольким фактическим заказчикам и это не считается конфликтом.
Пустые значения допустимы. Точные дубли объединяются. Предупреждение возникает только при конфликтующей привязке одного рудника. Свежесть не применяется.


## TypeRequest 1.0.0

Формат определяется по заголовкам `Краткое описание (типовой запрос)` и `Вид работ`; для первого поля также принимается заголовок `Краткое описание`.

Нормализованные поля: `requestKey`, `shortDescription`, `workType`.
Ключ `requestKey` строится из краткого описания после нормализации пробелов, NBSP и регистра. Пунктуация и формулировка не упрощаются.
Модуль ITSM использует этот ключ для точного сопоставления входной колонки `Краткое описание` с ожидаемым видом работ.

Точные дубли объединяются. Конфликт одного описания с несколькими видами работ выдаёт warning без потери записей. Свежесть не применяется.
