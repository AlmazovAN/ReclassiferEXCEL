# Technical backlog

Ниже зафиксированы **неблокирующие** доработки на будущее. Текущая архитектура и CI считаются рабочими; эти пункты нужны, чтобы не потерять известный технический долг.

| ID | Доработка | Сейчас | На будущее |
|---|---|---|---|
| TD-01 | Post-COMMIT check | После успешной записи Integration дополнительно сверяет Registry. | Перенести финальный invariant ближе к Repository/транзакции, чтобы после успешного COMMIT не возникала отдельная ошибка проверки. |
| TD-02 | Большой `REPLACE` | `REPLACE` выполняется синхронно. | При росте объёмов сделать пакетную async-запись с progress/yield/cancel/rollback по аналогии с крупным UPSERT. |
| TD-03 | Checksum HTML snapshot | Snapshot v1 использует короткую контрольную сумму для обнаружения повреждения. | Для следующего формата снимка перейти на SHA-256, сохранив чтение существующего v1. |
| TD-04 | Индекс поиска МБ | Поиск задач МБ по заявкам идёт построчно через SQLite без загрузки всего Dataset в JS. | Если объём/частота запросов вырастут, хранить и индексировать отдельный ключ заявки. |

Эти пункты не требуют немедленного рефакторинга и не должны блокировать развитие функциональности.
